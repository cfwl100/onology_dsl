# OAG 本体子图检索

## 本层职责
1. 使用用户输入的问题执行本体子图检索。
2. 拿到子图结果后，再结合 SOP 与子图信息规划下一步任务。
3. 不跳过检索步骤直接假设子图内容。

## 脚本顺序
1. 先运行 `python scripts/semantic_subgraph_search.py`，传入用户问题和本体id或整理后的检索 query和本体id。
2. 再根据返回的子图信息，提炼节点、关系、约束、候选操作。
3. 最后输出与 SOP 对齐的任务规划。

### 调用示例（必须按照示例格式调用）
```bash
# 直接传 JSON 字符串（不写文件）
python scripts/semantic_subgraph_search.py --query "设备故障诊断"
```

## 输入契约
至少需要：
- 用户问题或检索目标

可选增强信息：
- 业务上下文
- 目标对象范围
- 想解决的任务目标

## 输出契约
- 先简要概括检索到的子图重点。
- 再列出基于子图与 SOP 的下一步任务规划。
- 如果检索为空或噪声大，明确说明结果不足，不要虚构子图。

## 本层边界
- 不把子图检索替代成数据查询。
- 不在未获得子图结果时直接给出确定性路径结论。
- 不直接执行函数或写入数据，除非用户后续明确要求进入下一阶段。

## 校验规则
1. 先检索，再规划；不能反过来。
2. 不把子图检索结果说成完整事实库。
3. 子图为空时，不输出确定性路径或对象关系结论。
4. 任务规划必须显式基于"检索结果 + SOP"，而不是泛泛建议。

## 样例

### 样例 1：围绕问题检索子图
输入：帮我找出和"客户流失预警"相关的本体子图，并告诉我下一步应该怎么分析。
处理：
- 先检索相关子图
- 再输出子图摘要与后续分析任务

### 样例 2：带范围的检索
输入：请围绕订单履约相关主题检索子图，并给出排障 SOP。
处理：
- 保留"订单履约"主题
- 输出与履约相关的节点、关系和排障步骤

### 边界样例 3：问题太泛
输入：帮我检索一下本体。
应返回：问题范围过大，需要业务主题或任务目标。

### 边界样例 4：检索为空
输入：检索某个不存在主题。
应返回：说明未获得有效子图，不要虚构结果。
