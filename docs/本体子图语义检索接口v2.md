# 基于语义子图检索接口v2

## 接口描述

本体语义子图检索接口v2。该接口以自然语言问题query或者提取好的实体作为检索输入，在指定本体上检索子图。

该接口从输入参数自然语言问题query中提取实体或者提取好的实体查找匹配子图检索的种子，按照指定的检索策略执行子图检索。返回结果包括ObjectType、Property、Relationship、RelationshipProperty、Function和Action。

## URL

/v2/onto-retrieval/subgraph/semantic-search

## Method

POST

## Content-Type

application/json

## 请求参数

| 参数名称               | 参数类型 | 必选 | 数据类型 | 默认值  | 说明                                                         |
| ---------------------- | -------- | ---- | -------- | ------- | ------------------------------------------------------------ |
| ontologyId             | body     | 是   | String   | 无      | 本体ID，约束：1~256字符                                      |
| query                  | body     | 否   | String   | 无      | 自然语言问题，query和entities参数至少一个不为空。约束：1~1024字符 |
| entities               | body     | 否   | String   | 无      | 原始query提取好的实体，query和entities参数至少一个不为空。<br> 如果entities不为空，则优先使用entities，SGR不再做实体提取。<br> 约束：1~102400字符。结构：详见下方单独定义 |
| adaptiveRetrieval      | body     | 否   | int      | 1       | 是否自适应检索：<br>- 0：否<br>- 1：是<br>默认值：1，当开启自适应检索：<br>- 若本体规模 <= 阈值（默认300节点，即ObjectType+Property数），直接返回全量本体子图<br>- 若本体规模 > 阈值，退化为按检索策略检索。<br>软件场景传 `0`；传 `1` 时仍按阈值三分支判定 |
| seedRetrievalMode      | body     | 否   | String   | vector  | 种子节点检索模式：<br> - vector: 向量检索<br> - keyword: 关键词检索<br> - hybrid: 混合检索 |
| similarityThreshold    | body     | 否   | double   | 0.6     | 种子节点语义检索相似度匹配阈值，仅对seedRetrievalMode为vector和hybrid时有效，默认值0.6 |
| topk                   | body     | 否   | int      | 3       | 种子节点语义检索相似度匹配阈值内，取前k个结果，默认值3       |
| graphExpansionStrategy | body     | 否   | String   | minimal | 子图检索策略：<br> - minimal: 最小连通子图<br> - khop: 多源BFS<br> - component: 全连通分量 |
| hopLimit               | body     | 否   | int      | 3       | 种子节点向外扩散的深度，当graphExpansionStrategy=khop时该值为意义 |
| includeFunctions       | body     | 否   | int      | 0       | 是否返回Function，0：否，1：是，默认值：0                    |
| includeActions         | body     | 否   | int      | 0       | 是否返回Action，0：否，1：是，默认值：0                      |

> **软件场景参数组合**：软件场景**不是独立的接口流程**，而是 `entities` 非空 + `adaptiveRetrieval=0` + 配置中心 `enableObjectLinking=false` / `enablePropertyLinking=false` / `enablePropertyValueLinking=true`（配套 `includeAllProperties=true`）的一组参数组合。传 `adaptiveRetrieval=1` 时仍按阈值三分支判定（小本体直接返回全量本体子图）。详见 `IR20260729001097 SGR子图检索能力增强_27.3软件上车.md`。

#### 字段说明

`entities` 内各字段定义如下（取值形态见下方两例）：

| 字段名称                                              | 数据类型 | 必选 | 说明                                                         |
| ----------------------------------------------------- | -------- | ---- | ------------------------------------------------------------ |
| `entities`                                            | Object   | 否   | 切词结果的根对象；<br>HTTP 上以 JSON 字符串形式整体置于请求参数 `entities` 中（见「请求示例2」）。**`query` 与 `entities` 至少一个不为空**。<br>内含 `extractedEntities` 与 `propertyValues` 两个并列数组 |
| `entities.extractedEntities`                          | Object[] | 是   | **对象及其属性**：每项为一个对象（ObjectType）及该对象下识别到的属性。<br>**不可为空数组** —— 须至少给出一个对象；切词只给出属性值、未给出任何对象时的请求不合法 |
| `entities.extractedEntities[].objectType`             | String   | 是   | 对象名称。<br>软件场景切词侧已与本体 ObjectType 对齐，平台侧不再做实体提取。 |
| `entities.extractedEntities[].properties`             | String[] | 否   | 该对象下识别到的属性（Property）名称列表。<br>**可为空**；**软件场景已与软件侧约定不传该字段** —— 不传不影响结果（见下方「示例的范围」）。 |
| `entities.propertyValues`                             | Object[] | 否   | **属性值**：按 `objectType` 分组，每组给出该对象下若干「属性 → 取值」项 |
| `entities.propertyValues[].objectType`                | String   | 是   | 该组属性值所属的对象名称。**不可为空**<br>在该 `objectType` 指定的语义字段（`property` 已给出且非空）或**所有语义字段**（`property` 未给出 —— 省略或空串）中做属性值链接：一旦有命中，该 `objectType` 并入种子集，**参与子图构建**。 |
| `entities.propertyValues[].propertyValues`            | Object[] | 是   | 该对象下的属性值项列表                                       |
| `entities.propertyValues[].propertyValues[].property` | String   | 否   | 属性名称。<br>**未给出该字段**（**省略**或传空串 `""`，两者等价）即**不带 property 过滤条件**，在 `objectType` 下所有语义字段中做值链接 |
| `entities.propertyValues[].propertyValues[].value`    | String   | 是   | 属性的取值，**尚未与本体取值对齐** —— 规范值与数据值由属性值链接结果的 `valuesMapping[]`（`canonicalValue` / `defaultDataValue`）给出 |

「必选」为「否」的字段**可不传，也可传空值**（`extractedEntities[].properties` / `propertyValues` 传 `[]`、`property` 传空串 `""`），服务端一律按**「未给出」**处理 —— 因此 `"property": ""` 与**省略 `property`** 等价，都是**不带 property 过滤条件**。

同一个 `objectType` 可以**同时出现在两个数组里**（示例2 中的 `BonusBalanceBook`：`extractedEntities` 给出其属性 `balanceAmount`，`propertyValues` 给出 `bonusBalanceOperationType` / `paidFlag` 两个值），两个数组在【实体链接】阶段**合流**，共同决定种子节点。

> **示例的范围**：上表与下方两例中的 `extractedEntities[].properties` **仅为结构示意**。软件场景本期已与软件侧约定**不传该字段**，实际请求中 `extractedEntities` 只给出 `objectType` —— **这不影响结果**：**`seedNodes[]` 中的种子只有 `objectType`（各场景皆然）**，属性挂在所属对象下、体现在**返回子图**里，由 `includeAllProperties` 决定携带哪些（软件场景为 `true`，即每个对象携带**全量属性**）。故示例2 的 `balanceAmount` 由切词给不给都不改变最终结果。详见 `IR20260729001097 SGR子图检索能力增强_27.3软件上车.md`。

| 参数名称       | 必选 | 数据类型 | 默认值 | 说明                                                         |
| -------------- | ---- | -------- | ------ | ------------------------------------------------------------ |
| resultCode     | 是   | String   | 无     | 响应码，请求成功返回200，请求失败返回具体的错误码            |

### result 结构

`result` 为对象，按「响应示例2-1」的形态说明如下。JSON 键名均为小驼峰。

| 字段名称 | 数据类型 | 说明 |
| -------- | -------- | ---- |
| `result` | Object | 请求结果根对象；请求失败时为 `null` |
| `result.seedNodes` | Object[] | 种子节点，即实体链接的结果。**每项代表一个对象**，属性不作为种子节点（见下方注） |
| `result.seedNodes[].sourceObjectType` | String | 种子对象名称。软件场景不实际执行对象链接，与 `targetObjectTypes[].name` 取值相同 |
| `result.seedNodes[].targetObjectTypes` | Object[] | 该种子对象链接命中的本体 ObjectType 列表 |
| `result.seedNodes[].targetObjectTypes[].name` | String | 本体 ObjectType 的名称（系统标识） |
| `result.seedNodes[].targetObjectTypes[].id` | String | 本体 ObjectType 的 ID |
| `result.seedNodes[].targetObjectTypes[].score` | double | 对象链接的相似度得分 |
| `result.seedNodes[].targetObjectTypes[].propertyLinks` | Object[] | 该对象的属性链接结果 |
| `result.seedNodes[].targetObjectTypes[].propertyLinks[].sourceProperty` | String | 输入侧的属性名称 |
| `result.seedNodes[].targetObjectTypes[].propertyLinks[].targetProperties` | Object[] | 命中的本体 Property 列表 |
| `result.seedNodes[].targetObjectTypes[].propertyLinks[].targetProperties[].name` | String | 本体 Property 的名称（系统标识） |
| `result.seedNodes[].targetObjectTypes[].propertyLinks[].targetProperties[].id` | String | 本体 Property 的 ID |
| `result.propertyValuesLinks` | Object[] | 属性值链接结果，与 `seedNodes` **并列**的顶层数组，按 `objectType` 分组；示例1-2 中不出现 |
| `result.propertyValuesLinks[].sourceObjectType` | String | 该组属性值链接所属的对象名称 |
| `result.propertyValuesLinks[].id` | String | 该对象的 ID |
| `result.propertyValuesLinks[].valuesLinks` | Object[] | 该对象下的属性值链接项 |
| `result.propertyValuesLinks[].valuesLinks[].sourceProperty` | String | 输入侧的属性名称；**空串表示不带 property 过滤条件**（在该对象全部语义字段中检索），与请求侧 `property` 的语义一致 |
| `result.propertyValuesLinks[].valuesLinks[].id` | String | 命中属性的 ID |
| `result.propertyValuesLinks[].valuesLinks[].sourceValue` | String | 输入侧的属性取值（尚未与本体取值对齐） |
| `result.propertyValuesLinks[].valuesLinks[].valuesMapping` | Object[] | 该取值的本体取值映射候选；**零命中时为 `[]`** |
| `result.propertyValuesLinks[].valuesLinks[].valuesMapping[].canonicalValue` | String | 本体规范取值 |
| `result.propertyValuesLinks[].valuesLinks[].valuesMapping[].defaultDataValue` | String | 该规范取值对应的默认数据值 |
| `result.propertyValuesLinks[].valuesLinks[].valuesMapping[].score` | double | 取值匹配的相似度得分 |
| `result.nodes` | Object[] | 返回子图的节点 |
| `result.nodes[].id` | String | 节点 ID，对应本体 ObjectType / Property 的 ID |
| `result.nodes[].label` | String | 节点类型：`objectType` / `property` |
| `result.nodes[].properties` | Object | 节点属性，键值均为字符串；`display` / `description` / `primaryKeys` 的值为 JSON 字符串 |
| `result.nodes[].properties.dataType` | String | **属性节点的数据类型**，`label=property` 时返回（示例中所有属性节点均携带，取值如 `string` / `enum` / `number`）；`enum` 表示枚举类型，此时 `properties` 内另返回 `enumDataType`、节点上另返回 `propertyEnumValues`。取值以本体定义为准 |
| `result.nodes[].properties.enumDataType` | String | **枚举取值的实际数据类型**（示例中 `paymentType` 携带 `string`）；**仅 `label=property` 且 `properties.dataType=enum` 时返回**，`dataType` 为其他取值时不返回。取值以本体定义为准 |
| `result.nodes[].properties.display` | String | 显示名，JSON 字符串，如 `{"zh":"…","en":"…"}`（缺失语言的键可不出现） |
| `result.nodes[].properties.description` | String | 描述，JSON 字符串，形态同上 |
| `result.nodes[].properties.name` | String | 名称（系统标识） |
| `result.nodes[].properties.primaryKeys` | String | 主键 Property 的 ID 列表，JSON 数组字符串；示例中仅 ObjectType 节点携带 |
| `result.nodes[].propertyEnumValues` | Object[] | 该属性的**全部枚举取值**，默认返回（不需要请求中出现，也不限于本次命中的取值）；**仅 `label=property` 且 `properties.dataType=enum` 时返回** |
| `result.nodes[].propertyEnumValues[].value` | String | 规范取值 |
| `result.nodes[].propertyEnumValues[].isDefault` | String | 是否为默认取值：`"true"` / `"false"` |
| `result.nodes[].propertyEnumValues[].defaultDataValue` | String | 该取值对应的默认数据值 |
| `result.nodes[].propertyEnumValues[].description` | Object | 取值描述，含 `en` / `zh` 两个键 |
| `result.nodes[].propertyEnumValues[].synonyms` | Object | 该枚举取值的同义词，含 `en` / `zh` 两个**字符串数组**；**无同义词时省略该键**（示例中 `Prepaid` 携带，`Postpaid` / `Hybrid` 无该键） |
| `result.nodes[].propertyInstanceValues` | Object[] | Instance 类型的属性值走**属性值链接**，此处返回本次链接到的结果（`sourceValue` → `canonicalValue`）；该属性**支持语义检索**时返回 |
| `result.nodes[].propertyInstanceValues[].sourceValue` | String | 输入侧取值 |
| `result.nodes[].propertyInstanceValues[].canonicalValue` | String | 本体规范取值 |
| `result.edges` | Object[] | 返回子图的边 |
| `result.edges[].sourceId` | String | 起点节点 ID |
| `result.edges[].targetId` | String | 终点节点 ID |
| `result.edges[].edgeType` | String | 边类型：`has_property`（对象 → 属性）、`defines_relation`（对象间关系） |
| `result.edges[].propertyMap` | Object | 边的附加信息：`has_property` 边为 `{}`；`defines_relation` 边携带 `name` / `junctionConfig` / `businessSemanticDescription` |
| `result.edges[].propertyMap.name` | String | 关系名称（如 `IS_PARENT` / `IS_CHILD`） |
| `result.edges[].propertyMap.junctionConfig` | String | 关系连接配置，JSON 字符串 |
| `result.edges[].propertyMap.businessSemanticDescription` | String | 关系的业务语义描述，JSON 字符串 |
| `result.functions` | Object[] | 返回的 Function 列表，每项含 `name` / `description`；`includeFunctions=0` 时为空数组 |
| `result.functions[].name` | String | Function 名称 |
| `result.functions[].description` | String | Function 描述 |
| `result.actions` | Object[] | 返回的 Action 列表，每项含 `name` / `description`；`includeActions=0` 时为空数组 |
| `result.actions[].name` | String | Action 名称 |
| `result.actions[].description` | String | Action 描述 |

> **注（Property 节点的扩展字段）**：`label=property` 的节点在 `properties` 内返回 `dataType`；`dataType=enum` 时在 `properties` 内另返回 `enumDataType`（**枚举取值的实际数据类型**），并在节点上另返回 `propertyEnumValues` —— **该属性的全部枚举取值默认返回**，不取决于本次请求是否提到这些取值；每个枚举取值可携带 `synonyms`（`en` / `zh` 字符串数组，**无同义词时不返回该键**）；该属性**支持语义检索**时在节点上另返回 `propertyInstanceValues` —— Instance 类型的属性值走属性值链接，该字段即**链接得到的结果**。`label=objectType` 的节点不返回这些字段。响应示例2-1 的 property 节点均带 `properties.dataType`，其中 `paymentType`（`enum`）带 `properties.enumDataType`（`string`）与 `propertyEnumValues`，`balanceAmount` 带 `propertyInstanceValues`。

> **注（种子节点只有对象）**：`seedNodes[]` 中每项只代表一个对象，**属性不作为种子节点**，也不存在种子节点级的 `properties` 字段；属性挂在所属对象下，最终体现在返回子图的 `nodes` / `edges` 中，每个对象携带哪些属性由 `includeAllProperties` 配置决定（软件场景为全量属性）。

> **注（`nodes` / `edges` 的形态差异）**：响应示例1-2 的 `nodes` / `edges` 为另一套形态 —— `nodes[]` 使用 `id` / `type` / `display` / `description`，`edges[]` 使用 `id` / `name` / `display` / `elementType` / `objectRel` 等字段，且不含 `propertyValuesLinks`。本节的字段说明以响应示例2-1 的形态为准，两套形态是否统一〔待确认〕。

> **注（`propertyValuesLinks` 的保留范围）**：该数组回报属性值链接的证据，**未命中、因而未进入 `seedNodes[]` 的对象组**也可能原样保留（示例中的 `OrganizationPerspectiveView`）。是在丢弃后一并剔除、还是原样回报〔待确认〕。

## 请求示例1

POST /v2/onto-retrieval/subgraph/semantic-search

```json
{
	"query": "查找区域内CN层链路的流量损失情况",

	"topk": 1,
	"graphExpansionStrategy": "khop",
	"hopLimit": 3,
	"includeFunctions": 1,
	"includeActions": 1
}
```

## 接口约束

### 总体：本体子图检索能力边界：

基于语义相似度，从本体图中召回并构建一个受控规模的结构化子图，不负责推理、不保证业务正确性，仅提供高相关候选上下文。

### 1、本体模型质量要求：

子图检索效果强依赖于本体模型的语义质量。本体中的 ObjectType、Property、Relationship 必须具备完整、无歧义的名称与语义描述，并保持建模一致性与稳定性。任何语义缺失、歧义或建模不一致，都会直接导致语义索引偏移，从而降低子图检索的召回准确率与结构合理性。

#### 1.1 本体语义完备性约束

- ObjectType、Property、Relationship 必须具备：
  - 唯一标识（ID）
  - 清晰名称（Name）
  - 语义描述（Description）
- 禁止：
  - 模糊命名（如：data1, info, temp）
  - 过度复用同名不同义
- 违反则导致：
  - embedding 语义漂移检索召回错误

#### 1.2 本体建模一致性约束

- 同一语义对象不能在同一本体内多个 ObjectType 中重复建模（避免“语义分裂”）
- Property 归属必须稳定（避免跨类型漂移），如trafficKPI是Link的属性，而不是Ne的属性。
- Relationship 必须具备明确方向和语义定义

### 2、查询接口能力边界

#### 2.1 子图检索接口不承担“复杂推理”

- 子图检索接口的职责：
  - 语义召回 + 图结构扩展
- 子图检索接口的职责不包括：
  - 多跳逻辑推理
  - 规则推导
  - 业务决策

#### 2.2 子图检索接口不保证强语义正确性

- 接口只保证：
  - Top-K 语义相关性
- 不保证：
  - 100% 业务正确无歧义解释

#### 2.3 查询能力约束

- 子图查询接口query支持：
  - 关键词 / 自然语言
  - 指定ObjectType或Property
  - 跳数限制（hop_limit）
- 本体子图检索接口不是“通用图查询引擎”，故不支持：
  - 任意 nGQL 执行
  - 任意路径表达式
