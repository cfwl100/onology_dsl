# upsert / batch 模式与边界

## 何时使用 UPSERT

- 用户语义是“存在则更新，不存在则创建”
- 可以识别出稳定匹配键

## 何时使用 BATCH

- 一次请求中明确包含多个步骤
- 明确要求整体原子执行，或强烈暗示需要整体提交

## 关键边界

- 如果没有稳定匹配键，不要猜测 `matchBy`
- 如果多步处理之间没有明确边界，不要擅自拆出 `items`
- 如果用户没有表达多步或原子要求，不要默认升级为 `BATCH`

## 示例

### 正例：UPSERT

用户：如果 orderNo=ORD-001 存在就更新状态，否则创建新订单

### 正例：BATCH

用户：先更新订单状态，再创建发票，且整体原子执行

### 反例

用户：把订单状态改为已支付

这是单步更新，应交给 `UPDATE` 插件。
