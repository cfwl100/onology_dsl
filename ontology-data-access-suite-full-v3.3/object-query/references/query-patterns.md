# 查询模式与边界

## 适用模式

- 查询单个对象
- 查询对象列表
- 基于条件筛选对象
- 多对象逻辑读取（但不是显式关系路径）

## 常见线索

- “查询状态为 X 的订单”
- “列出名称包含 Y 的站点”
- “返回设备 id、name、status”

## 不属于本插件的情况

- “统计 / 分组 / top n / 平均值” → 交给聚合插件
- “从 A 经过关系 r 到 B” → 交给关联路径插件
- “查询订单对应的发票”且明显是一跳单关系 → 交给 link-query 插件

## 示例

### 正例

用户：查询状态为 completed 的订单，返回订单号和金额

应生成：`QUERY`

### 反例

用户：按 region 统计订单数量

不应继续生成 `QUERY`，应改走聚合插件。
