# 审查结果与修改说明

## 逐项判断

### 1. name 字段去实现前缀：部分合理，已优化
- 合理点：去掉 `oql-` / `oac-` 这类实现前缀，可以降低下层技能对具体协议名的暴露。
- 保留点：名称仍需保持任务边界清晰，不能改成含义模糊的名字。
- 本次采用：`association-query`、`object-query`、`aggregate-query`、`create-object`、`update-object`、`delete-object`、`upsert-batch`、`execute-request`。

### 2. 增加 `whenToUse` 字段：不合理，未采纳
Claude Code 官方 frontmatter 支持的核心字段是 `name`、`description`、`tools`，并未定义 `whenToUse`。
本次改为把“何时使用”的信息直接写入 `description`。

### 3. 将 `allowed-tools` 改成 `allowed_tools`：不合理，已改为 `tools`
Claude Code 官方 frontmatter 使用的是 `tools`，不是 `allowed-tools`，也不是 `allowed_tools`。
因此本次统一改为 `tools`。

### 4. description 去实现细节：合理，已优化
所有子技能的 `description` 已改成基于任务意图和触发条件的表述，不再在 frontmatter 中直接暴露 OQL/OAC 术语。

### 5. 顶层补路由说明、减少重复：部分合理，已局部优化
- 顶层补充了简洁的路由线索。
- 但未引入顶层 `common-rules.md`。原因是当前套件已经要求每个子目录下的 `references/` 只保留该目录相关的 OQL 规范与举例；再抽一个顶层公共 OQL 规则文件会重新把实现细节上移到顶层，并增加跨目录耦合。
