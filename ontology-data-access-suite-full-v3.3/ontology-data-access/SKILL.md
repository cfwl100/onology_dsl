# 本体对象数据访问

把本 Skill 当作面向 agent 的稳定入口。

本层只负责识别访问意图、判定缺失项，并把请求路由到最合适的 **S-OQL 生成插件**。本层不展开底层结构细节，也不在文本层描述 canonical 展开规则。

## 本层职责

1. 判断用户是在读取、路径导航、单跳关联、统计、创建、更新、删除，还是 upsert / 批量处理。
2. 识别当前请求缺少哪些关键信息。
3. 只在需要时选择一个最合适的下层生成插件。
4. 只有在已经拿到完整可执行请求时，才直接交给执行插件。

## 路由线索

- 普通读取 → `object-query`
- 显式关系路径或多跳遍历 → `association-query`
- 单一关系的一跳获取 → `link-query`
- 统计或分组 → `aggregate-query`
- 创建 → `create-object`
- 更新 → `update-object`
- 删除 → `delete-object`
- upsert 或批处理 → `upsert-batch`
- 已经得到完整可执行请求 → `execute-request`

## 本层边界

- 不在本层解释对象字段、关系字段、canonical 展开规则或执行协议。
- 不在本层默认做多步编排；除非用户明确要求原子批处理。
- 不在本层猜测对象、关系、字段、匹配键或执行模式。
- 不在本层直接手写转换后的结构；统一交给下层插件和脚本。

## 判断原则

- 先判定请求属于哪一种操作语义。
- 再判断请求是否缺少对象范围、关系路径、筛选条件、返回字段、匹配键或执行范围。
- 只有在已经能稳定识别意图时，才选择一个最合适的下层实现。
- 若信息不足，优先返回结构化缺失项，而不是强行猜测。

## 行为约束

- 默认只选择一个主下层实现。
- 对缺失信息的反馈要具体，不要使用笼统描述。
- 下层已经给出结构化错误时，不要改写错误语义。
- 顶层不要输出教学性协议解释。

## 输出前必须逐项检查（Checklist）

在给出最终输出前，必须逐项自检，全部满足后才可输出：

1. **入口边界**：只处理“本体对象访问意图”，不展开底层结构细节。
2. **意图判定**：先判定读/关联/聚合/创建/更新/删除/upsert/batch。
3. **缺失项识别**：识别对象范围、关系路径、筛选条件、返回字段、匹配键、执行范围是否缺失。
4. **最小充分路由**：只选择一个最合适的下层实现，不做不必要多步编排。
5. **禁止越权**：不在本层猜测对象字段、关系字段或执行模式。
6. **结果语义**：成功与错误语义如实传递，不擅自重写。
7. **结构合法性**：若下发结构化请求，需满足目标下层 skill 的输入结构要求。
8. **缺失信息处理**：信息不足时返回结构化错误并明确需补充内容。
