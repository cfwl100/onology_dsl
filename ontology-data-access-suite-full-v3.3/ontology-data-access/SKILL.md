# 本体对象数据访问

把本 Skill 当作面向 agent 的稳定入口。  
本层只承载“本体对象访问”的自然语言意图，不展开内部协议、请求格式、编译术语或执行细节。

## 本层职责
1. 判断用户是在读取、关联导航、统计、创建、更新、删除，还是存在则更新 / 批量处理。  
2. 识别当前请求缺少哪些关键信息。  
3. 只在需要时选择一个最合适的下层实现。  
4. 如实传递下层返回的成功结果或错误语义。

## 路由线索
- 普通读取 → 选择普通读取下层实现  
- 显式关系路径或多跳遍历 → 选择关联读取下层实现  
- 单一关系的一跳获取 → 选择单跳关联下层实现  
- 统计或分组 → 选择聚合读取下层实现  
- 创建 / 更新 / 删除 / 存在则更新 / 批量处理 → 选择对应写入下层实现  
- 已经得到完整结构化请求 → 直接交给执行器

## 本层边界
- 不在本层解释服务名、协议名、请求格式。  
- 不在本层解释对象字段、关系字段、编译规则或执行协议。  
- 不在本层默认做多步编排；除非用户明确要求多步原子处理。  
- 不在本层猜测对象、关系、字段、匹配键或执行模式。

## 判断原则
- 先判断用户是在读取、关联导航、统计、创建、更新、删除，还是存在则更新 / 批量处理。  
- 再判断请求是否缺少对象范围、关系路径、筛选条件、返回字段、匹配键或执行范围。  
- 只有在已经能稳定识别意图时，才选择一个最合适的下层实现。  
- 顶层只表达访问意图与缺失信息，不展开内部实现细节。

## 行为约束
- 默认只选择一个主下层实现。  
- 对缺失信息的反馈要具体，不要使用笼统描述。  
- 下层已经给出结构化错误时，不要改写错误语义。  
- 顶层不要输出内部实现术语的教学性解释。
