# SEC 多维查询场景识别规则

本文件用于指导 `sec-multidim` 业务 Skill 识别用户原始问题，并用自然语言方式委托平台能力。这里不定义平台扩展协议，不要求平台识别 workflow 字段。

## 1. 场景分类

### S1：不跨对象查询维度

用户只查询单对象下的维度、属性、指标或度量。

处理方式：

- 自然语言委托平台走 `QUERY`。
- 只声明一个业务对象。
- 过滤条件只落到该对象的字段上。
- 返回字段只包含用户要求的维度、属性、指标或度量。

### S2：跨对象关联相同指标/度量，且用户显式指定多个维度

示例：

```text
查询栅格为 A、小区为 B 的 RSRP。
```

处理方式：

- 识别为组合维度查询。
- 自然语言委托平台走 `QUERY`。
- 查询对象包括 `grid` 和 `cell`。
- 栅格条件落在 `grid` 对象，小区条件落在 `cell` 对象。
- 返回字段包括组合维度和指标，例如 `DIM_GRID`、`DIM_CELL`、`C_RSRP`。
- 优先表达 DAC 多维模型后端倾向，但不直接生成 DAC 私有请求。

### S3：跨对象关联相同指标/度量，用户表达“对应 / 归属”

示例：

```text
查询栅格 A 对应的小区的 RSRP。
```

处理方式：

- 先判断多维模型是否支持“栅格维度过滤并返回小区维度”。
- 如果支持，仍然自然语言委托平台走 `QUERY`，不要因为用户说“归属”就强制走 `ASSOCIATION_QUERY`。
- 查询条件只包含栅格维度，返回小区维度和指标。
- 在自然语言委托中说明：这是“归属过滤的多维查询”，如平台生成 OQL 支持扩展参数，可表达维度升维诉求。

### S4：跨对象未关联相同指标/度量，但用户显式指定多个维度

示例：

```text
查询栅格为 A、小区为 B 的 PRB。
```

处理方式：

- 用户已经给出完整组合维度，因此优先按组合维度查询处理。
- 自然语言委托平台走 `QUERY`。
- 过滤条件包含 `DIM_GRID=A` 和 `DIM_CELL=B`。
- 返回字段包括 `DIM_GRID`、`DIM_CELL`、`C_PRB`。
- 若映射不全导致无记录，结果为空即为空。

### S5：跨对象未关联相同指标/度量，且不存在维表升维

示例：

```text
查询栅格 A 对应的小区的 PRB。
```

处理方式：

- 不能把栅格条件直接塞入小区 PRB 查询。
- 必须由本业务 Skill 规划两次自然语言平台调用：
  1. 第一次走 `ASSOCIATION_QUERY`，通过栅格 A 查询归属小区的 `CELL_ID`。
  2. 第二次走 `QUERY`，用第一步返回的 `CELL_ID` 查询小区 `C_PRB`。
- 两步之间的结果读取和条件填充由本业务 Skill 自己完成，不交给平台 Skill 作为结构化协议。

## 2. 关键判断原则

1. “跨对象”不一定等于 `ASSOCIATION_QUERY`。
2. 如果用户给出了完整组合维度，通常优先走 `QUERY`。
3. 如果只是表达“归属”，且多维模型支持维度升维，也优先走 `QUERY`。
4. 只有需要沿关系链获取目标对象主键时，才走 `ASSOCIATION_QUERY`。
5. 平台 OAC 返回空结果是正常结果，不应重复查询。
