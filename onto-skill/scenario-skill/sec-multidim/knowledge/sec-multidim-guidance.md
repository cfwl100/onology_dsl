# SEC 多维查询业务定制规则文件

本文是 `scenario-skill/sec-multidim` 的必填业务定制文件，用于向 `Ontology-based-planning-skill` 注入 SEC 多维查询的场景知识、流程级定制和步骤级定制。

本文件不是平台协议文件，不直接要求平台识别业务私有结构；它用于指导 Planning 层基于 OAG 本体子图规划 OAC 查询和 Function 调用任务。

---

## 1. 场景知识

SEC 多维查询面向栅格、小区、网络对象、指标、度量、时间分表和 DAC 多维模型等场景。常见业务问题包括：

- 查询单对象属性、维度、指标或度量。
- 查询栅格维度和小区维度组合条件下的指标明细。
- 查询栅格对应或归属小区的指标。
- 查询 PRB、RSRP 等指标的分组统计、TopN、平均值、最大值、最小值。
- 基于对象 Function 标准化对象上下文后，再执行数据访问。

核心原则：

1. 业务定制文件内容优先级高于 Planning 和 Platform 默认模板。
2. 业务规则可以覆盖默认流程、默认输入模板、默认输出模板和执行规则。
3. 对象、字段、关系、函数候选仍必须以 OAG 子图和平台返回结果为准；业务规则不能编造平台不存在的事实。
4. OAC 最终输出必须是对象结构 `{objects, relationships}`。
5. 空结果是合法结果，不自动放宽条件、不自动换路径、不伪造结果。
6. 对外只使用公共 `本体ID`，不要同时填写 `ontologyId` 和 `schemaRef`。

## 2. 流程级定制

按照用户问题和决策表选择执行步骤。

| 场景ID | 用户表达特征 | 业务场景 | 推荐步骤 | 关键说明 |
|---|---|---|---|---|
| S1 | 只查询单对象维度、属性、指标或度量 | 单对象查询 | S1 -> S2 -> S3 -> S4 -> S7 | OAG 找对象和字段，S3 规划单对象 QUERY。 |
| S2 | 用户显式给出栅格 A、小区 B，并查询 RSRP 等可组合指标 | 组合维度查询，相同指标/度量 | S1 -> S2 -> S3 -> S4 -> S7 | 将 `DIM_GRID`、`DIM_CELL` 作为过滤条件。 |
| S3 | 用户说“栅格 A 对应/归属的小区的 RSRP” | 归属过滤的多维查询 | S1 -> S2 -> S3 -> S4 -> S7 | 如果 DAC 多维模型支持维度升维，不要强制走关系路径。 |
| S4 | 用户显式给出栅格 A、小区 B，并查询 PRB 等不完全同源指标 | 组合维度查询，不同指标/度量 | S1 -> S2 -> S3 -> S4 -> S7 | 用户已给全组合维度，先按多维事实查询；映射不全时结果为空即为空。 |
| S5 | 用户说“栅格 A 对应/归属的小区 PRB”，且业务判断不支持维表升维 | 关系主键解析 + 指标查询 | S1 -> S2 -> S3 -> S4a -> S4b -> S7 | 先查 `CELL_ID`，再用 `CELL_ID` 查 `C_PRB`。 |
| S6 | 用户要求统计、分组、TopN、平均值、最大值、最小值、计数 | 聚合统计 | S1 -> S2 -> S3 -> S4 -> S7 | S3 规划 AGGREGATE，S4 执行聚合查询。 |
| S7 | 用户要求先标准化对象、补齐对象上下文，再查询数据 | Function 前置查询 | S1 -> S2 -> S3 -> S5 -> S6 -> S4 -> S7 | Function 返回结果进入后续 OAC 过滤条件。 |

### 决策优先级

1. 用户显式给出完整组合维度时，优先表达为“查询组合维度指标明细”。
2. 用户表达“对应 / 归属”时，先判断是否支持多维模型维度升维。
3. 支持维度升维时，仍优先表达为“查询归属过滤下的指标明细”。
4. 不支持维度升维且必须沿关系链获取目标主键时，才拆成“按关系路径查询小区主键” + “按主键查询小区指标明细”。
5. 涉及统计、分组、TopN、平均值、最大值、最小值、计数时，表达为“聚合统计/分组统计”。
6. 明确需要对象标准化、上下文补齐或函数计算时，规划 Function 前置。

## 3. 步骤级定制

### 3.1 S2 子图检索规则

S2 必须检索本场景所需的对象、字段、关系和函数候选。

```text
子图检索规则：
- 检索 grid、cell、多维事实对象、EPC网络、指标对象等相关对象。
- 检索 DIM_GRID、GRID_ID、DIM_CELL、CELL_ID、C_RSRP、C_PRB、3600、release_cause 等属性候选。
- 用户表达“对应/归属”时，需要返回 grid 到 cell 的关系候选，但是否使用关系路径由 S3 决定。
- 需要 Function 前置补齐上下文时，需要返回 result.functions。
- 返回结构保留 result.seedNodes、result.nodes、result.edges、result.functions、result.actions 原始字段，同时输出对象、字段归属、关系候选、函数候选摘要。
```

### 3.2 S3 基于本体子图的任务规划规则

S3 必须结合 OAG 子图和本业务规则生成可执行任务。

```text
默认规划规则：
1. 识别任务目标：明细查询、关系路径查询、聚合统计、Function 前置或组合任务。
2. 确认查询对象、起点对象、终点对象。
3. 从 OAG 子图读取字段归属、关系候选、函数候选。
4. 根据流程级定制选择 S4、S4a/S4b、S5/S6 或 S7。
5. 生成每个任务的 actionType、输入模板、依赖关系、预期输出、失败策略。
6. 如果业务规则和子图冲突，以子图为平台事实来源，输出冲突或缺失说明。
```

规划时的默认选择：

- 单对象问题：规划单对象 `QUERY`。
- 完整组合维度问题：规划组合维度 `QUERY`。
- 归属过滤问题：先判断维度升维；支持则 `QUERY`，不支持则两步 OAC。
- 统计问题：规划 `AGGREGATE`。
- Function 前置问题：规划 S5/S6，再将函数结果写入 S4 条件。

### 3.3 S4 OAC 查询规则

S4 必须按对象结构输出。中间过程的 operation 判断、OQL、validation 可以打印，但不作为最终输出字段。

```text
查数据
本体ID：<公共本体ID>
操作类型：<查询对象属性 / 查询组合维度指标明细 / 查询归属过滤下的指标明细 / 按关系路径查询主键 / 按主键查询指标明细 / 分组统计 / TopN 查询>
查询对象：<来自子图 objectType，例如 grid g、cell c、EPC网络 e>
关系路径：<仅关系路径查询时填写；关系名必须来自 defines_relation.properties.name；普通明细查询写无关系路径>
过滤条件：<用户条件及其对应字段依据；包含时间范围；说明单位、枚举值、ID/NAME 口径>
返回要求：<返回字段、排序、分组、maxResults、空结果策略>
执行要求：先生成并校验 OQL；通过后再执行；结果为空视为有效结果，不自动放宽条件重试。
期望输出：只返回对象结构结果，包含 objects 和 relationships；不输出 operationDecision、oql、validation。
```

### 3.4 S5/S6 Function 调用规则

仅在 Function 前置或函数计算场景使用。

```text
函数调用规则：
1. 根据 OAG result.functions 中的 description 选择目标函数。
2. 提取 properties.ontologyId 和 properties.id。
3. 调用 get_params_spec(ontology_id, function_id)。
4. 解析 physicalName。
5. 组装 params。
6. 调用 call_function(physicalName, function_id, params)。
7. 缺少必填参数时返回缺失项，不得猜测。
```

### 3.5 S7 汇总规则

S7 汇总时必须保留：

- OAC 最终对象结构 `{objects, relationships}`。
- 使用的业务场景规则和关键决策依据。
- 若是两步 OAC，说明第一步结果如何进入第二步过滤条件。
- 若结果为空，说明空结果是有效结果。
- 若缺失对象、字段、关系、函数或参数规格，输出缺失项。

## 4. 字段口径表

| 业务说法 | 对象 | 推荐字段 | 字段口径 | 使用场景 | 注意事项 |
|---|---|---|---|---|---|
| 栅格维度 | `grid` | `DIM_GRID` | 多维模型维度 | 组合维度查询、维度升维过滤 | 用于 DAC 多维模型查询条件。 |
| 栅格主键 | `grid` | `GRID_ID` | 对象主键/关系链主键 | 通过关系查询小区主键 | 不要和 `DIM_GRID` 混用。 |
| 小区维度 | `cell` | `DIM_CELL` | 多维模型维度 | 返回小区维度、组合维度过滤 | 用于多维模型返回或过滤。 |
| 小区主键 | `cell` | `CELL_ID` | 对象主键/关系链主键 | 关系链解析后查询小区指标 | S5 第二步使用。 |
| RSRP | `cell` 或多维事实 | `C_RSRP` | 指标/度量 | 栅格、小区组合维度下的覆盖指标 | 通常支持组合维度查询。 |
| PRB | `cell` 或多维事实 | `C_PRB` | 指标/度量 | 小区资源利用相关指标 | 若无法通过栅格维度升维查询，需要先解析 `CELL_ID`。 |
| SEC 时间字段 | `EPC网络` 等 | `3600` | 采样时间/分表时间字段 | XDR/SDR/SEC 分表时间过滤 | 时间范围必须进入过滤条件，不能只写扩展说明。 |
| 释放原因 | `EPC网络` 等 | `release_cause` | 维度字段 | 需要 ID/NAME 双口径时使用 | 名称维度应表达为 `NAME(release_cause)` 或等价能力。 |

字段使用禁忌：

1. 多维过滤优先使用 `DIM_*` 字段，关系主键解析优先使用 `*_ID` 字段。
2. 只有 `cell c` 对象时，条件不能写到 `g.CELL_ID`。
3. 返回 ID 和返回名称不是同一件事，必须在委托中说明。
4. 不确定字段是否存在时，由 OAG 子图结果确认，不要臆造字段。

## 5. 时间语义决策表

| 用户时间表达或属性描述 | 时间口径 | 规划与查询要求 | 扩展表达 |
|---|---|---|---|
| 最近 5 分钟、最近 1 小时、最近一天 | 默认场景时间口径 | 若用户未说明 UTC/本地时间，按 SEC 默认本地时间处理；过滤条件包含起止时间。 | 如默认本地时间，表达 `localtime="true"`。 |
| 本地时间、北京时间、当地时间，或时间属性描述为“本地时间” | 本地时间 | 明确按本地时间解释；时间范围必须进入过滤条件。 | 如生成 OQL 支持 extensions，添加 `localtime="true"`。 |
| UTC 时间、按 UTC 查，或时间属性描述为“UTC 时间” | UTC | 明确按 UTC 时间解释；时间范围必须进入过滤条件。 | 如生成 OQL 支持 extensions，添加 `localtime="false"`。 |
| 今天、昨天、本周、本月 | 自然日/自然周期 | 先转换为起止时间，再作为过滤条件。 | 结合具体口径填写 `localtime`。 |
| 用户未指定时间 | 场景默认 | 明确采用默认时间策略，或在高风险场景提示缺少时间。 | 默认策略若为本地时间，表达 `localtime="true"`。 |

时间规则：

1. 时间范围必须进入 `过滤条件`。
2. `extensions.localtime` 只表示时间口径，不表示时间范围。
3. 不再使用旧的 `extensions.sec.partitionTime.timeMode` 作为首选表达。
4. 不要把时间条件写成物理 SQL 片段。

## 6. ID / NAME 维度表达规则

### 6.1 ID 维度

用户表达 ID、编号、标识、主键、唯一标识、原因码等含义时，识别为 ID 维度。

自然语言委托写法：

```text
返回字段需要按 ID 维度表达。生成 OQL 时，如果支持维度函数，请使用 ID(field) 或平台已注册的等价函数；如果不支持，请明确返回该字段的标识维度，不要返回名称维度。
```

### 6.2 NAME 维度

用户表达名称、显示名、中文名、业务名称、释放原因名称等含义时，识别为 NAME 维度。

自然语言委托写法：

```text
返回字段需要按名称维度表达。生成 OQL 时，如果支持维度函数，请使用 NAME(field) 或平台已注册的等价函数；如果不支持，请明确返回该字段的名称维度，不要返回 ID 维度。
```

## 7. 正例与反例

### 7.1 查询栅格 A、小区 B 的 RSRP

正例：

```text
业务意图：查询栅格维度 A 和小区维度 B 组合条件下的小区 RSRP 指标明细。
流程级定制：执行 S1/S2/S3/S4/S7，不执行 Function。
步骤级定制：S2 检索 grid、cell、DIM_GRID、DIM_CELL、C_RSRP；S3 规划组合维度明细 QUERY；S4 过滤 DIM_GRID=A、DIM_CELL=B 和时间范围，返回 DIM_GRID、DIM_CELL、C_RSRP。
```

反例：

```text
错误：因为涉及 grid 和 cell 两个对象，就强制使用关联路径查询。
```

原因：用户已经给出完整组合维度，不需要沿关系链查主键。

### 7.2 查询栅格 A 对应的小区 RSRP

正例：

```text
如果多维模型支持通过 DIM_GRID 过滤并返回 DIM_CELL，则流程级定制为 S1/S2/S3/S4/S7；S3 规划归属过滤下的明细 QUERY；S4 使用 DIM_GRID=A 查询并返回 DIM_CELL、C_RSRP。
```

反例：

```text
错误：只要用户说“对应/归属”，就一定使用关联路径查询。
```

原因：归属语义不等于一定要走关系路径；如果 DAC 多维模型支持维度升维，明细查询更直接。

### 7.3 查询栅格 A 对应的小区 PRB，且不存在维表升维

正例：

```text
流程级定制：执行 S1/S2/S3/S4a/S4b/S7。
S4a：按栅格到小区关系路径查询小区主键，通过 grid g 的 GRID_ID=A 沿 locateIn 关系查询 cell c 的 CELL_ID。
S4b：读取 S4a 返回的 CELL_ID，再按小区主键查询 PRB 指标明细，过滤条件为 c.CELL_ID 属于第一步返回结果，返回 c.CELL_ID 和 c.C_PRB。
```

反例：

```text
错误：直接用 g.DIM_GRID=A 查询 c.C_PRB，但业务知识已确认 PRB 不支持栅格维度升维。
```

## 8. 两步查询执行规则

当场景需要拆成两次 OAC 时，业务 Skill 必须按以下规则注入 Planning：

1. 第一步 OAC：自然语言委托平台完成关系或主键发现查询。
2. Planning/S7 读取第一步结果。
3. 如果第一步结果为空，停止后续查询，返回空对象结构和原因说明。
4. 如果第一步返回一个值，把该值写入第二次 OAC 的过滤条件。
5. 如果第一步返回多个值，优先在第二次 OAC 中说明使用 `IN` 条件。
6. 如果平台不支持 `IN`，由 Planning 规划多次 OAC 查询并在 S7 合并结果。
7. 不把变量绑定、步骤依赖作为平台协议传递给 OAC。

标准表达：

```text
第一步查询 grid A 归属的小区 CELL_ID。
如果第一步返回 CELL_ID=B，则第二步委托平台查询 cell 对象，过滤条件为 c.CELL_ID 等于 B，返回 c.CELL_ID 和 c.C_PRB。
如果第一步返回多个 CELL_ID，则第二步使用 IN 条件；如果平台不支持 IN，则规划多次查询并合并结果。
```

## 9. 扩展说明边界

业务 Skill 可以在自然语言委托中说明扩展诉求，例如：

- SEC 组合维度查询。
- 优先按 DAC 多维模型映射处理。
- 本次是分表时间查询。
- 本次按本地时间或 UTC 时间解释。
- 属性描述为“本地时间”时，如生成 OQL 支持 extensions，请添加 `localtime="true"`。
- 属性描述为“UTC 时间”时，如生成 OQL 支持 extensions，请添加 `localtime="false"`。
- 如生成 OQL 支持 extensions，可表达 `targetBackend=DAC`、`dimensionLift=true`、`relationResolve=GRID_TO_CELL` 等已约定扩展诉求。

禁止：

1. 在自然语言中写物理 SQL、GQL、TQL。
2. 直接生成 DAC 私有请求结构。
3. 使用扩展说明绕过 schema、mapping 或能力校验。
4. 把跨步骤变量绑定交给平台 Skill。
