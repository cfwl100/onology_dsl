# SEC 多维查询业务定制规则手册

本文是 `sec-multidim` 业务 Skill 的主规则文件，用于指导 Agent 在不修改 `platform-skill` 的前提下，通过自然语言方式完成 SEC 多维查询场景定制。

本文件只描述 SEC 业务规则。OAC 通用自然语言委托模板、自检清单、`schemaRef` 环境变量规则、中文自然语言操作类型和 `extensions.localtime` 规则，以平台文档为准：

```text
../../platform-skill/Ontology-platform-unified-skill/references/oac-data-access.md
```

---

## 1. 基本原则

1. 不修改、不覆盖、不要求平台稳态 Skill 识别新增业务协议。
2. 业务 Skill 负责业务语义理解、场景分类、步骤规划、上一步结果读取和下一步条件填充。
3. 平台 Skill 只接收当前这一步的自然语言委托。
4. 每次 OAC 委托必须按平台 `oac-data-access.md` 的模板和自检清单表达。
5. `schemaRef` 可不在每次委托中填写；缺省时由执行环境变量 `ONTOLOGY_SCHEMA_REF` 提供；若用户或业务显式传入，则覆盖环境变量。
6. 操作类型使用中文自然语言动作，不强制填写 `QUERY`、`ASSOCIATION_QUERY`、`AGGREGATE` 英文枚举。
7. 不能把 `workflowId`、`stepId`、`dependsOn`、`variableBinding` 作为平台协议传递。
8. 不直接生成物理 SQL、GQL、TQL 或 DAC 私有请求；只表达“优先按 DAC 多维模型映射处理”等业务诉求。
9. OAC 返回空结果是合法结果，不重复查询，不伪造结果。

## 2. SEC 多维查询决策表

| 场景ID | 用户表达特征 | 业务场景 | 是否跨对象 | 是否表达归属 | 是否依赖维表升维 | 推荐自然语言操作类型 | 调用方式 | 关键说明 |
|---|---|---|---:|---:|---:|---|---|---|
| S1 | 只查询单对象维度、属性、指标或度量 | 单对象查询 | 否 | 否 | 否 | 查询对象属性 / 查询指标明细 | 一次 OAC 自然语言委托 | 只声明一个对象，条件和返回字段都落在该对象上。 |
| S2 | 用户显式给出栅格 A、小区 B，并查询 RSRP 等可组合指标 | 组合维度查询，相同指标/度量 | 是 | 否 | 否 | 查询组合维度指标明细 | 一次 OAC 自然语言委托 | 将 `DIM_GRID`、`DIM_CELL` 作为过滤条件，返回组合维度和指标。 |
| S3 | 用户说“栅格 A 对应/归属的小区的 RSRP” | 归属过滤的多维查询 | 是 | 是 | 是 | 查询归属过滤下的指标明细 | 一次 OAC 自然语言委托 | 不要因为出现“归属”就强制关联路径查询；若 DAC 多维模型支持维度升维，优先明细查询。 |
| S4 | 用户显式给出栅格 A、小区 B，并查询 PRB 等不完全同源指标 | 组合维度查询，不同指标/度量 | 是 | 否 | 否 | 查询组合维度指标明细 | 一次 OAC 自然语言委托 | 用户已给全组合维度，先按多维事实查询；映射不全时结果为空即为空。 |
| S5 | 用户说“栅格 A 对应/归属的小区 PRB”，且业务知识判断不支持维表升维 | 关系主键解析 + 指标查询 | 是 | 是 | 否 | 按关系路径查询小区主键 + 按主键查询小区指标明细 | 两次 OAC 自然语言委托 | 先查 `CELL_ID`，再用 `CELL_ID` 查 `C_PRB`。 |
| S6 | 用户要求统计、分组、TopN、平均值、最大值、最小值、计数 | 聚合统计 | 视场景而定 | 视场景而定 | 视场景而定 | 分组统计 / 统计数量 / 求平均值 / TopN 查询 | 一次 OAC 自然语言委托 | 必须填写聚合要求，包括分组字段、指标函数、排序限制。 |
| S7 | 用户要求先标准化对象、补齐对象上下文，再查询数据 | Function 前置查询 | 视场景而定 | 视场景而定 | 视场景而定 | 先调用函数补齐上下文，再查询数据 | Function + OAC | Function 的结果读取和条件填充由业务 Skill 自己完成。 |

### 决策优先级

1. 用户显式给出完整组合维度时，优先表达为“查询组合维度指标明细”。
2. 用户表达“对应 / 归属”时，先判断是否支持多维模型维度升维。
3. 支持维度升维时，仍优先表达为“查询归属过滤下的指标明细”。
4. 不支持维度升维且必须沿关系链获取目标主键时，才拆成“按关系路径查询小区主键” + “按主键查询指标明细”。
5. 涉及统计、分组、TopN、平均值、最大值、最小值、计数时，表达为“聚合统计/分组统计”，并补充聚合要求。

## 3. OAC 委托写法要求

业务 Skill 不维护独立 OAC 模板。每次委托平台数据访问能力时，按平台 `oac-data-access.md` 的字段表和自检清单生成自然语言请求。

### 3.1 通用自检

提交给平台前，本 Skill 需要确认：

1. 操作类型已用中文自然语言动作说明，例如“查询小区指标明细”“按栅格到小区关系查询”“按小区分组统计平均 PRB”。
2. 查询对象已说明对象类型、别名和用途。
3. 返回字段已说明返回哪个对象或关系的哪些字段，不使用 `*`。
4. `schemaRef` 若不填写，需要确认运行环境提供 `ONTOLOGY_SCHEMA_REF`；如果业务显式传入，则以传入值为准。
5. 关联路径类请求必须写清关系路径、方向、起点对象、终点对象。
6. 聚合统计类请求必须写清分组字段、指标函数、指标别名、排序限制和聚合后过滤。
7. 时间范围必须写入过滤条件，不能只写在扩展说明中。
8. 扩展说明只能补充已约定的扩展诉求，不能替代对象、关系、条件和返回字段。

### 3.2 委托示例

```text
请调用本体平台的数据访问能力，按如下要求生成并执行 OQL：

1. schemaRef：不填写，使用环境变量 ONTOLOGY_SCHEMA_REF。
2. 操作类型：查询栅格和小区组合维度下的 RSRP 指标明细。
3. 操作选择依据：用户已经给出完整组合维度，不需要沿关系路径查询主键。
4. 查询对象：grid，别名 g，用于栅格维度过滤；cell，别名 c，用于小区维度和指标返回。
5. 关系路径：无关系路径。
6. 过滤条件：g.DIM_GRID 等于 A；c.DIM_CELL 等于 B；时间字段 3600 大于等于开始时间且小于结束时间。
7. 返回字段：g.DIM_GRID、c.DIM_CELL、c.C_RSRP。
8. 聚合要求：无聚合。
9. 排序/限制：最多返回 100 条。
10. 时间要求：3600 是时间字段；如果属性描述为本地时间，按本地时间解释，并在扩展说明中表达 localtime="true"。
11. 扩展说明：这是 SEC 组合维度查询，优先按 DAC 多维模型映射处理；如果生成 OQL 支持 extensions，请添加 localtime="true"。
12. 结果处理：保留 OAC 原始字段，结果为空即为空。
```

## 4. 字段口径表

| 业务说法 | 对象 | 推荐字段 | 字段口径 | 使用场景 | 注意事项 |
|---|---|---|---|---|---|
| 栅格维度 | `grid` | `DIM_GRID` | 多维模型维度 | 组合维度查询、维度升维过滤 | 用于 DAC 多维模型查询条件。 |
| 栅格主键 | `grid` | `GRID_ID` | 对象主键/关系链主键 | 通过关系查询小区主键 | 不要和 `DIM_GRID` 混用。 |
| 小区维度 | `cell` | `DIM_CELL` | 多维模型维度 | 返回小区维度、组合维度过滤 | 用于多维模型返回或过滤。 |
| 小区主键 | `cell` | `CELL_ID` | 对象主键/关系链主键 | 关系链解析后查询小区指标 | S5 第二步使用。 |
| RSRP | `cell` 或多维事实 | `C_RSRP` | 指标/度量 | 栅格、小区组合维度下的覆盖指标 | 通常支持组合维度查询。 |
| PRB | `cell` 或多维事实 | `C_PRB` | 指标/度量 | 小区资源利用相关指标 | 若无法通过栅格维度升维查询，需要先解析 `CELL_ID`。 |
| SEC 时间字段 | `EPC网络` 等 | `3600` | 采样时间/分表时间字段 | XDR/SDR/SEC 分表时间过滤 | 时间范围必须进入过滤条件，不能只写扩展说明。 |
| 释放原因 | `EPC网络` 等 | `release_cause` | 维度字段 | 需要 ID/NAME 双口径时使用 | 名称维度应表达为 `NAME(release_cause)` 或等价能力。 |

### 字段使用禁忌

1. 多维过滤优先使用 `DIM_*` 字段，关系主键解析优先使用 `*_ID` 字段。
2. 只有 `cell c` 对象时，条件不能写到 `g.CELL_ID`。
3. 返回 ID 和返回名称不是同一件事，必须在委托中说明。
4. 不确定字段是否存在时，先委托平台检索本体或查询子图，不要臆造字段。

## 5. 时间语义决策表

| 用户时间表达或属性描述 | 时间口径 | 自然语言委托要求 | 扩展表达 |
|---|---|---|---|
| 最近 5 分钟、最近 1 小时、最近一天 | 默认场景时间口径 | 若用户未说明 UTC/本地时间，明确“按 SEC 默认本地时间处理”；过滤条件包含起止时间。 | 如默认本地时间，表达 `localtime="true"`。 |
| 本地时间、北京时间、当地时间，或时间属性描述为“本地时间” | 本地时间 | 明确按本地时间解释；时间范围必须进入过滤条件。 | 如生成 OQL 支持 extensions，添加 `localtime="true"`。 |
| UTC 时间、按 UTC 查，或时间属性描述为“UTC 时间” | UTC | 明确按 UTC 时间解释；时间范围必须进入过滤条件。 | 如生成 OQL 支持 extensions，添加 `localtime="false"`。 |
| 今天、昨天、本周、本月 | 自然日/自然周期 | 先转换为起止时间，再作为过滤条件。 | 结合具体口径填写 `localtime`。 |
| 用户未指定时间 | 场景默认 | 明确采用默认时间策略，或在高风险场景提示缺少时间。 | 默认策略若为本地时间，表达 `localtime="true"`。 |

### 时间规则

1. 时间范围必须进入 `过滤条件`。
2. `extensions.localtime` 只表示时间口径，不表示时间范围。
3. 时间属性描述为“本地时间”时，扩展说明中表达 `localtime="true"`。
4. 时间属性描述为“UTC 时间”时，扩展说明中表达 `localtime="false"`。
5. 不再使用旧的 `extensions.sec.partitionTime.timeMode` 作为本场景的首选表达；统一按平台 OAC 手册中的 `extensions.localtime` 规则表达。
6. 不要把时间条件写成物理 SQL 片段。

## 6. ID / NAME 维度表达规则

### 6.1 ID 维度

用户表达以下含义时，识别为 ID 维度：

- ID、编号、标识、主键、唯一标识。
- 接口 ID、小区 ID、网元 ID、原因码。

自然语言委托写法：

```text
返回字段需要按 ID 维度表达。生成 OQL 时，如果支持维度函数，请使用 ID(field) 或平台已注册的等价函数；如果不支持，请明确返回该字段的标识维度，不要返回名称维度。
```

### 6.2 NAME 维度

用户表达以下含义时，识别为名称维度：

- 名称、显示名、中文名、业务名称。
- 接口名称、小区名称、释放原因名称。

自然语言委托写法：

```text
返回字段需要按名称维度表达。生成 OQL 时，如果支持维度函数，请使用 NAME(field) 或平台已注册的等价函数；如果不支持，请明确返回该字段的名称维度，不要返回 ID 维度。
```

### 6.3 正确示例

```text
请查询 EPC网络 对象的 release_cause 和 release_cause 名称。返回字段中 release_cause 按原始 ID 维度返回；release_cause_name 按名称维度返回。生成 OQL 时，如果支持维度函数，请使用 NAME(release_cause) 表达名称维度。
```

### 6.4 反例

```text
错误：只返回 release_cause，并声称它同时表示 ID 和名称。
```

原因：ID 维度和 NAME 维度是两个不同的业务口径。

## 7. 场景正例与反例

### S2：查询栅格 A、小区 B 的 RSRP

正例：

```text
操作类型使用“查询栅格和小区组合维度下的 RSRP 指标明细”。查询对象为 grid g 和 cell c。过滤条件为 g.DIM_GRID=A、c.DIM_CELL=B。返回字段为 g.DIM_GRID、c.DIM_CELL、c.C_RSRP。说明这是 SEC 组合维度查询，优先按 DAC 多维模型映射处理。
```

反例：

```text
错误：因为涉及 grid 和 cell 两个对象，就强制使用关联路径查询。
```

原因：用户已经给出完整组合维度，不需要沿关系链查主键。

---

### S3：查询栅格 A 对应的小区 RSRP

正例：

```text
如果多维模型支持通过 DIM_GRID 过滤并返回 DIM_CELL，则操作类型使用“查询归属过滤下的小区 RSRP 指标明细”。过滤条件为 g.DIM_GRID=A，返回字段为 c.DIM_CELL、c.C_RSRP，并说明这是归属过滤的多维查询，可表达 dimensionLift=true。
```

反例：

```text
错误：只要用户说“对应/归属”，就一定使用关联路径查询。
```

原因：归属语义不等于一定要走关系路径；如果 DAC 多维模型支持维度升维，明细查询更直接。

---

### S4：查询栅格 A、小区 B 的 PRB

正例：

```text
操作类型使用“查询栅格和小区组合维度下的 PRB 指标明细”。过滤条件为 g.DIM_GRID=A、c.DIM_CELL=B。返回字段为 g.DIM_GRID、c.DIM_CELL、c.C_PRB。若映射不全导致无记录，结果为空即为空。
```

反例：

```text
错误：因为 PRB 主要属于小区，就忽略用户给出的栅格维度 A。
```

原因：用户显式给出了组合维度，应尽量保留过滤条件。

---

### S5：查询栅格 A 对应的小区 PRB，且不存在维表升维

正例：

```text
第一步操作类型使用“按栅格到小区关系路径查询小区主键”。通过 grid g 的 GRID_ID=A 沿 locateIn 关系查询 cell c 的 CELL_ID。
第二步由业务 Skill 读取第一步返回的 CELL_ID，再发起“按小区主键查询 PRB 指标明细”，过滤条件为 c.CELL_ID 属于第一步返回结果，返回 c.CELL_ID 和 c.C_PRB。
```

反例：

```text
错误：直接用 g.DIM_GRID=A 查询 c.C_PRB，但业务知识已确认 PRB 不支持栅格维度升维。
```

原因：该场景必须先解析目标小区主键，再查目标对象指标。

## 8. 两步查询自然语言执行规则

当场景需要拆成两次平台调用时，业务 Skill 必须按以下规则执行：

1. 第一步：自然语言委托平台完成关系或主键发现查询。
2. 业务 Skill 读取第一步结果。
3. 如果第一步结果为空，停止后续查询，返回空结果和原因说明。
4. 如果第一步返回一个值，把该值写入第二次委托的过滤条件。
5. 如果第一步返回多个值，优先在第二次委托中说明使用 `IN` 条件。
6. 如果平台不支持 `IN`，业务 Skill 拆成多次自然语言查询，再合并结果。
7. 不把变量绑定、步骤依赖作为平台协议传递。

标准表达：

```text
第一步查询 grid A 归属的小区 CELL_ID。
如果第一步返回 CELL_ID=B，则第二步委托平台查询 cell 对象，过滤条件为 c.CELL_ID 等于 B，返回 c.CELL_ID 和 c.C_PRB。
如果第一步返回多个 CELL_ID，则第二步使用 IN 条件；如果平台不支持 IN，则本业务 Skill 拆成多次查询。
```

## 9. 扩展说明的表达边界

业务 Skill 可以在自然语言委托中说明扩展诉求，例如：

- SEC 组合维度查询。
- 优先按 DAC 多维模型映射处理。
- 本次是分表时间查询。
- 本次按本地时间或 UTC 时间解释。
- 属性描述为“本地时间”时，如生成 OQL 支持 extensions，请添加 `localtime="true"`。
- 属性描述为“UTC 时间”时，如生成 OQL 支持 extensions，请添加 `localtime="false"`。
- 如生成 OQL 支持 extensions，可表达 `targetBackend=DAC`、`dimensionLift=true`、`relationResolve=GRID_TO_CELL` 等已约定扩展诉求。

但禁止：

1. 在自然语言中写物理 SQL、GQL、TQL。
2. 直接生成 DAC 私有请求结构。
3. 使用扩展说明绕过 schema、mapping 或能力校验。
4. 把跨步骤变量绑定交给平台 Skill。
