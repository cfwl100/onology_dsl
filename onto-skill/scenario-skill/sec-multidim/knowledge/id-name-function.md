# ID / NAME 维度函数语义

## 1. 背景

SEC 多维模型中，同一个维度字段可能同时存在“ID 维度”和“名称维度”两种使用方式。业务 Skill 必须在自然语言委托中说清楚用户要的是 ID 还是名称，避免平台把两者混为同一个字段。

## 2. 语义规则

### ID 维度

用户表达以下含义时，识别为 ID 维度：

- 查询接口 ID
- 查询小区 ID
- 查询网元 ID
- 查询标识、编号、主键、唯一标识

自然语言委托中应写：

```text
返回字段需要按 ID 维度表达。生成 OQL 时，如果支持维度函数，请使用 ID(field) 或平台已注册的等价函数；如果不支持，请明确返回该字段的标识维度，不要返回名称维度。
```

### NAME 维度

用户表达以下含义时，识别为名称维度：

- 查询接口名称
- 查询小区名称
- 查询释放原因名称
- 查询显示名、中文名、业务名称

自然语言委托中应写：

```text
返回字段需要按名称维度表达。生成 OQL 时，如果支持维度函数，请使用 NAME(field) 或平台已注册的等价函数；如果不支持，请明确返回该字段的名称维度，不要返回 ID 维度。
```

## 3. 禁止规则

1. 不要把 ID 和 NAME 当作同一个返回字段。
2. 不要把 `NAME(release_cause)` 简化为普通字段 `release_cause`。
3. 不要在业务 Skill 中直接生成 DAC 私有结构。
4. 如果平台未注册 ID / NAME 维度函数，应说明能力缺失，而不是猜测字段。

## 4. 自然语言委托示例

```text
请调用本体平台的数据访问能力，查询 EPC网络 对象的 release_cause 和 release_cause 名称。返回字段中 release_cause 按原始 ID 维度返回；release_cause_name 按名称维度返回。生成 OQL 时，如果支持维度函数，请使用 NAME(release_cause) 表达名称维度。
```
