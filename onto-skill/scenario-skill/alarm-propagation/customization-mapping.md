# alarm-propagation 自然语言定制注入说明

## 1. 目标

本文说明如何把 `alarm-propagation` 原有自然语言业务知识无损注入到 `Ontology-based-planning-skill`。

新的原则是：**不强制拆成固定字段，优先保留自然语言知识原文和执行约束**。

上层业务 Skill 只需要识别主意图、读取对应 knowledge 文件，并把知识中的关键内容以自然语言定制说明传给 planning 层。

---

## 2. 通用注入格式

推荐传给 planning 层的内容如下：

```text
场景：alarm-propagation
用户原始问题：<用户输入原文>
本体子图检索本体ID：network@1.0
本体访问schemaRef：network@1.0
业务意图：<当前唯一主意图>
已读取知识：knowledge/<xxx>.md
业务知识与规则：<完整保留 knowledge 原文中的目标、核心经验知识、调用规则、执行建议、禁止项、返回要求、空结果策略>
执行定制要求：<按 knowledge 原文改写默认 S2 子图检索和 S4 本体访问提示；未明确的信息由本体子图和平台结果确认>
```

结构化字段可选，不再是必填接口。

---

## 3. 查询网元告警

读取文件：`knowledge/nealarm.md`。

自然语言注入时必须保留：

- 告警和异常事件不同，不查 AbnormalStatus。
- `alarmName` 是告警类型；查询特定告警时使用 `identifier`。
- 告警数据可能很多，如果子图存在合适函数，可优先发现函数。
- 查询网元告警时直接用 `ne.name` 作为过滤条件，不需要先查网元 ID。
- 返回字段必须包含 knowledge 文件要求的告警属性。
- 关系路径必须由本体子图返回结果推断。

推荐定制语句：

```text
读取 knowledge/nealarm.md。查询网元告警时不要查 AbnormalStatus；直接使用网元名称作为 ne.name 过滤条件；返回 knowledge 中要求的告警字段；如果子图返回合适函数，可以优先发现函数；关系路径由本体子图确认。
```

---

## 4. 传播关系分析

读取文件：`knowledge/propagation.md`。

自然语言注入时必须保留：

- 不查 AbnormalStatus。
- `alarmName` 是告警类型，`identifier` 是唯一标识。
- PathNE、RingNE、SingleNE、CrossNE 的传播规则。
- Function 不是对象类型，禁止对 Function 做模型查询。
- 每个 Function 只能调用一次。
- OAG 固定自然语言检索问题必须保留。
- 获取 Function 传播知识后，不再执行 OAC 备选方案。
- 传播知识子图或 Function 结果不等于传播链成立，必须实例验证。

推荐定制语句：

```text
读取 knowledge/propagation.md。按文件中的固定自然语言问题检索传播知识子图；优先从子图函数候选中发现传播知识函数；同一函数只能调用一次；如果函数已返回传播知识，不再执行本体访问备选方案；传播知识不代表传播链成立，后续必须实例验证。
```

---

## 5. 传播证据验证

读取文件：`knowledge/evidence.md`。

自然语言注入时必须保留：

- 规划哪些方向完全由用户输入决定。
- 用户输入几个方向就规划几个方向，未指定方向时输出缺失项。
- 多个方向必须按用户输入顺序串行执行。
- 每个方向必须独立调用一次本体子图检索，禁止合并，禁止重复。
- 不同方向的网元名称和告警列表可能不同，必须分别处理。
- 固定本体子图检索模板必须按 knowledge 原文使用。
- 禁止使用 Function、Port，禁止关系中包含 Port、Link。
- 返回字段、过滤条件、message_type 和空结果不重试规则必须保留。

推荐定制语句：

```text
读取 knowledge/evidence.md。验证方向完全由用户输入决定；每个方向独立规划、独立检索子图、独立生成本体访问查询；多个方向按用户输入顺序串行执行，禁止合并和重复；每个方向使用 knowledge 中固定自然语言模板；禁止 Function、Port 以及 Port/Link 关系；空结果视为有效结果，不重试。
```

---

## 6. 防信息丢失检查清单

业务 Skill 委托 planning 前自检：

1. 是否保留用户原始问题？
2. 是否说明读取了哪个 knowledge 文件？
3. 是否保留禁止项、固定模板、返回字段和空结果策略？
4. 是否保留方向顺序和每个方向独立上下文？
5. 是否避免直接生成最终查询语言？
6. 是否把对象、字段、关系和函数确认交给本体子图和平台结果？

## 7. 示例输入模式选择

| 用户问题 | 推荐模式 |
|---|---|
| 帮我查询某网元的告警 | 业务定制模式，自然语言注入 `nealarm.md`。 |
| 帮我分析某网元的故障传播 | 业务定制模式，自然语言注入 `propagation.md`。 |
| 按同站点、对端网元检查传播证据 | 业务定制模式，自然语言注入 `evidence.md`，按方向规划。 |
| 外部系统已经给出完整步骤 | 显式步骤执行模式。 |
