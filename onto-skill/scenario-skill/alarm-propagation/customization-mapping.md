# alarm-propagation 自然语言定制注入说明

## 1. 目标

本文说明如何把 `alarm-propagation` 原有自然语言业务知识无损注入到 `Ontology-based-planning-skill`。

新的原则是：**不强制拆成固定字段，优先保留自然语言知识原文和执行约束；对外只传一个公共本体ID；业务定制拆成流程级定制和步骤级定制两部分**。

上层业务 Skill 只需要识别主意图、读取对应 knowledge 文件，并把知识中的关键内容以自然语言定制说明传给 planning 层。

---

## 2. 通用注入格式

推荐传给 planning 层的内容如下：

```text
本体ID：network@1.0
业务意图：<基于用户输入和当前 knowledge 改写后的详细自然语言任务，包含目标、实体、方向、范围、返回要求和期望动作>
已读取业务定制文件：knowledge/<xxx>.md
业务知识与规则：<完整保留 knowledge 原文中的目标、核心经验知识、调用规则、执行建议、禁止项、返回要求、空结果策略>
流程级定制：<执行全部默认步骤还是部分步骤；多方向是否串行；是否跳过 Function；是否追加汇总>
步骤级定制：<分别说明 S2 子图检索、S3 基于子图规划、S4 OAC 查询、S5/S6 Function、S7 汇总的输入、输出和执行规则>
缺失信息：<无法确认的信息；没有则写无>
```

结构化字段可选，不再是必填接口。

不要再分别填写“本体子图检索本体ID”和“本体访问 schemaRef”。对外本体是一个整体，只填写公共 `本体ID`。

## 3. 查询网元告警

读取文件：`knowledge/nealarm.md`。

自然语言注入时必须保留：

- 告警和异常事件不同，不查 AbnormalStatus。
- `alarmName` 是告警类型；查询特定告警时使用 `identifier`。
- 告警数据可能很多，如果子图存在合适函数，可优先发现函数。
- 查询网元告警时直接用 `ne.name` 作为过滤条件，不需要先查网元 ID。
- 返回字段必须包含 knowledge 文件要求的告警属性。
- 关系路径必须由本体子图返回结果推断。

推荐定制语句：

```text
本体ID：network@1.0
业务意图：查询指定网元上的告警数据，使用用户提供的网元名称作为 ne.name 过滤条件；如果用户指定具体告警唯一标识，则使用 identifier 过滤；返回 knowledge/nealarm.md 要求的告警字段。
已读取业务定制文件：knowledge/nealarm.md
业务知识与规则：告警和异常事件不同，不查 AbnormalStatus；alarmName 表示告警类型，identifier 表示告警唯一标识；关系路径由本体子图确认。
流程级定制：默认执行 S1/S2/S3/S4/S7；如子图发现可直接满足查询目标的函数候选，可规划 S5/S6；不执行传播路径或证据验证步骤。
步骤级定制：S2 检索网元、告警、告警属性相关子图；S3 规划单对象或必要关系查询任务；S4 使用 ne.name、identifier 等过滤条件并返回 knowledge 要求字段；S7 保留空结果说明。
缺失信息：没有则写无。
```

## 4. 传播关系分析

读取文件：`knowledge/propagation.md`。

自然语言注入时必须保留：

- 不查 AbnormalStatus。
- `alarmName` 是告警类型，`identifier` 是唯一标识。
- PathNE、RingNE、SingleNE、CrossNE 的传播规则。
- Function 不是对象类型，禁止对 Function 做模型查询。
- 每个 Function 只能调用一次。
- OAG 固定自然语言检索问题必须保留。
- 获取 Function 传播知识后，不再执行 OAC 备选方案。
- 传播知识子图或 Function 结果不等于传播链成立，必须实例验证。

推荐定制语句：

```text
本体ID：network@1.0
业务意图：分析指定网元或告警的传播关系，按 PathNE、RingNE、SingleNE、CrossNE 的传播规则获取传播知识，并说明这些传播知识是否还需要后续实例验证。
已读取业务定制文件：knowledge/propagation.md
业务知识与规则：按文件中的固定自然语言问题检索传播知识子图；优先从子图函数候选中发现传播知识函数；同一函数只能调用一次；如果函数已返回传播知识，不再执行本体访问备选方案。
流程级定制：默认执行 S1/S2/S3/S5/S6/S7；Function 只调用一次；不执行 OAC 备选，除非业务文件明确要求。
步骤级定制：S2 使用 propagation.md 固定检索问题；S3 基于子图规划函数任务；S5/S6 从 result.functions 按 description 选择传播知识函数；S7 输出传播规则和是否需要实例验证。
缺失信息：没有则写无。
```

## 5. 传播证据验证

读取文件：`knowledge/evidence.md`。

自然语言注入时必须保留：

- 规划哪些方向完全由用户输入决定。
- 用户输入几个方向就规划几个方向，未指定方向时输出缺失项。
- 多个方向必须按用户输入顺序串行执行。
- 每个方向必须独立调用一次本体子图检索，禁止合并，禁止重复。
- 不同方向的网元名称和告警列表可能不同，必须分别处理。
- 固定本体子图检索模板必须按 knowledge 原文使用。
- 禁止使用 Function、Port，禁止关系中包含 Port、Link。
- 返回字段、过滤条件、message_type 和空结果不重试规则必须保留。

推荐定制语句：

```text
本体ID：network@1.0
业务意图：验证用户指定方向上的告警传播证据；用户指定几个方向就规划几个方向，每个方向独立检索本体子图、独立生成本体访问查询，并分别返回证据结果或空结果说明。
已读取业务定制文件：knowledge/evidence.md
业务知识与规则：验证方向完全由用户输入决定；多个方向按用户输入顺序串行执行；每个方向独立调用一次本体子图检索，禁止合并和重复；禁止 Function、Port 以及 Port/Link 关系；空结果视为有效结果，不重试。
流程级定制：本意图不调用 Function；每个方向串行执行 S2/S3/S4/S7；未指定方向时结束并说明缺失。
步骤级定制：S2 每个方向使用 evidence.md 固定自然语言模板；S3 每个方向独立基于子图规划证据查询任务；S4 只使用子图确认过的对象、字段和关系；S7 每个方向单独输出证据结果或空结果说明。
缺失信息：未指定方向时返回缺失方向；否则写无。
```

## 6. 防信息丢失检查清单

业务 Skill 委托 planning 前自检：

1. 是否写清楚公共 `本体ID`？
2. 是否把短意图改写为详细自然语言 `业务意图`？
3. 是否说明读取了哪个 knowledge 文件？
4. 是否区分了流程级定制和步骤级定制？
5. 是否保留禁止项、固定模板、返回字段和空结果策略？
6. 是否保留方向顺序和每个方向独立上下文？
7. 是否避免直接生成最终查询语言？
8. 是否把对象、字段、关系和函数确认交给本体子图和平台结果？
