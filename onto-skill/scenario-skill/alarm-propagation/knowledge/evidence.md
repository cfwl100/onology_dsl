# 传播证据验证知识

本文档用于业务定制开发人员维护“传播证据验证”场景的 Planning 输入片段。外层 `alarm-propagation/SKILL.md` 只读取本文件、替换变量，并组装为 6 行输入后传递给 `Ontology-based-planning-skill`。

---

## 本体ID

**填写值：**

```text
network@1.0
```

**填写说明：**

- 固定填写公共本体 ID。
- 不在本文件中填写 `schemaRef`、内部模型 ID 或执行脚本路径。

---

## 业务意图

**填写模板：**

```text
验证起始网元 ${neName} 在 ${directions} 范围内，是否存在名称属于 ${alarmNames} 的活动告警证据，并返回相关网元和告警对象结构。
```

**变量说明：**

- `${neName}`：用户指定的起始网元名称。
- `${directions}`：用户指定的检查方向，例如同站点、对端网元、业务路径。
- `${alarmNames}`：用户指定的告警类型列表；长列表在外层 Skill 中保留为变量引用。

---

## 业务领域知识

### 场景知识

传播证据验证用于回答“某个网元周边或相关链路上是否存在活动告警证据”。传播知识或子图结果不等于传播链已经成立，必须通过实例层活动告警结果进行证据验证。

### 业务规则

- 检查方向完全由用户输入决定，外层 Skill 不得臆测补充方向。
- 支持的方向包括：同站点/同机房、对端网元、业务路径。
- 多方向场景中，每个方向独立处理；不同方向可以使用不同的网元名称和告警列表。
- `alarmName` 表示告警类型，不是告警唯一标识；特定告警实例可使用 `identifier`。

### 子图检索规则

- 同站点/同机房：从起始网元定位其所在站点或机房，再定位相关网元和活动告警。
- 对端网元：从起始网元定位对端关系，再定位对端网元上的活动告警。
- 业务路径：从起始网元定位所属业务路径，再定位同路径相关网元上的活动告警。
- 关系名称以本体子图返回为准，不在业务 Skill 中硬编码。

### 任务规划规则

- 按用户输入的方向顺序生成任务计划。
- 每个方向生成独立任务，不能把多个方向合并成一个任务。
- 规划结果应明确对象、关系路径、过滤条件、返回字段和 message_type。

### 查询规则

- 起点过滤使用起始网元名称。
- 告警过滤使用该方向对应的告警类型列表。
- 查询结果需要返回起始网元、相关网元和告警对象结构。
- 某方向查询为空时，表示该方向未发现指定活动告警证据，是有效结果，不自动放宽条件重试。

### Function 规则

默认不启用 Function。只有用户或业务知识明确要求使用 Function 时，才在流程级定制中追加 S4/S5。

### 返回要求和失败策略

- 返回证据结论、方向、命中告警、相关网元和缺失信息。
- 缺少方向时，填写缺失信息并停止组装该方向任务。
- 缺少网元名称或告警列表时，填写缺失信息，不得猜测补齐。

## 流程级定制

**默认填写：**

```text
使用默认流程 S1 -> S2 -> S3 -> S6；不执行 S4/S5 Function；每个方向独立处理；S3 空结果视为有效结果。
```

**填写说明：**

- 只写相对默认流程的覆盖项。
- 传播证据验证默认不启用 Function。
- 多方向时保留“每个方向独立处理”。

---

## 步骤级定制

**默认填写：**

```text
S1：按用户指定方向检索起始网元、相关中间对象、相关网元和告警对象子图；S2：为每个方向独立生成查询任务；S3：按方向查询活动告警并返回对象结构；S6：按方向汇总是否存在传播证据。
```

**填写说明：**

- 只写业务增量规则，不重复 Planning 默认步骤模板。
- 如果某一步无特殊业务规则，可写“使用默认步骤模板”。

---

## 缺失信息

**默认填写：**

```text
无
```

**填写规则：**

- 缺少起始网元时填写：`缺少起始网元名称`。
- 缺少检查方向时填写：`缺少传播证据检查方向`。
- 缺少告警列表时填写：`缺少待验证告警类型列表`。
