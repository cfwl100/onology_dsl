# 传播证据验证知识

本文档用于业务定制开发人员维护“传播证据验证”场景的 Planning 输入内容。外层 `alarm-propagation/SKILL.md` 读取本文件时，不能只摘录摘要；必须把下列分段中的原始业务规则合并到 6 行输入的 `业务领域知识`、`流程级定制`、`步骤级定制` 和 `缺失信息` 中，再传递给 `Ontology-based-planning-skill`。

---

## 本体ID

**填写值：**

```text
network@1.0
```

**填写说明：**

- 固定填写公共本体 ID。
- 不在本文件中填写 `schemaRef`、内部模型 ID 或脚本路径。

---

## 业务意图

**填写模板：**

```text
验证起始网元 ${neName} 在 ${directions} 范围内，是否存在名称属于 ${alarmNames} 的活动告警证据，并返回相关网元和告警对象结构。
```

**变量说明：**

- `${neName}`：用户指定的起始网元名称。
- `${directions}`：用户指定的检查方向，例如同站点、同机房、对端网元、业务路径。
- `${alarmNames}`：用户指定的待验证告警类型列表；长列表在外层 Skill 中保留为变量引用。
- 多方向时可拆分为 `${neName_same_site}`、`${neName_peer_ne}`、`${neName_service_path}`，以及 `${alarmNames_same_site}`、`${alarmNames_peer_ne}`、`${alarmNames_service_path}`。

---

## 业务领域知识

### 场景知识

传播证据验证用于回答“某个网元周边、对端或业务路径上是否存在支持传播分析的活动告警证据”。传播知识、分类知识或本体子图结果不等于传播证据已经成立，必须通过实例层活动告警查询结果进行验证。

支持的方向：

| directionKey | 方向名称 | 目的 |
|---|---|---|
| `same_site` | 同站点/同机房 | 找到起始网元同站点或同机房范围内的告警证据。 |
| `peer_ne` | 对端网元 | 找到与起始网元通过对端关系相连的其他网元，并查询这些网元上的活动告警。 |
| `service_path` | 业务路径 | 找到与起始网元同属业务路径的其他网元，并查询这些网元上的活动告警。 |

### 业务规则

- 检查方向完全由用户输入决定，外层 Skill 不得臆测补充方向。
- 用户输入“三步[同站点、对端网元、业务路径]”时，按用户顺序组织三个方向。
- 用户输入“两步[同站点、对端网元]”时，按用户顺序组织两个方向。
- 用户只输入“同站点/同机房”时，只组织 `same_site` 方向。
- 每个方向独立组织业务知识、子图检索规则、任务规划规则、查询规则和汇总规则；禁止把多个方向合并成一个泛化规则。
- `alarmName` 表示告警类型，不是单条告警唯一标识；单条告警实例应使用 `identifier`。
- 长告警列表必须变量化保存，6 行输入中优先引用变量名，只有最终查询参数需要时才允许展开完整列表。

### 关系名动态获取

关系名必须从本体子图返回的关系事实中动态获取，不能固定在代码、配置或业务 Skill 里。

- 关系名从本体子图的 `edges.properties.name` 获取。
- `businesspath` 是对象类型（objectType），不是关系边。
- `pathThrough` 只能作为业务路径方向的候选关系名，不允许硬编码。
- 如果本体子图返回的边名称不是 `pathThrough`，必须使用子图返回的实际名称。
- 同站点、对端网元、业务路径方向都必须以 S1 子图返回的实际对象、字段、关系为准。
- 字段归属必须由子图确认；不能凭经验把字段挂到对象上。

**强制要求：**

- 业务路径方向的关系名必须从 `edges.properties.name` 获取。
- 如子图返回 `pathThrough`，使用 `pathThrough`；如返回其他实际关系名，使用返回名称。
- 子图没有给出可用关系时，应在缺失信息或 S6 汇总中说明关系缺失，不得自行编造关系。

### 子图检索规则

- `same_site`：检索起始网元、站点/机房、告警相关对象，以及同站点范围所需的关系候选。
- `peer_ne`：检索起始网元、对端网元、告警相关对象，以及对端关系候选。
- `service_path`：检索起始网元、`businesspath` 对象、同路径网元、告警相关对象，以及业务路径关系候选。
- 子图输出中必须保留对象候选、字段归属、关系候选、关系方向、缺失对象、缺失字段和路径冲突信息。
- 每个方向只允许组织一次子图检索规则；多方向不能合并为一个子图检索问题。

### 任务规划规则

- 必须基于本体子图事实规划，不得凭经验写死对象名、字段名或关系名。
- 每个方向生成独立查询任务。
- 规划结果需要明确：起点对象、方向中间对象、目标告警对象、关系路径、过滤条件、返回字段、message_type 和空结果策略。
- 禁止规划 Port、Link 路径，除非业务知识和子图都明确要求。
- 不能用 Function 替代默认 OAC 查询，除非流程级定制明确追加 S4/S5。

### 查询约束

- 当方向为 `同站点` 时，查询路径禁止 `site -> ne -> alarm` 这种“站点再经过网元连接告警”的绕行路径；应使用本体子图中支持同站点证据验证的实际关系路径。如果子图只返回绕行路径而没有合法路径，应输出路径冲突或缺失说明。
- 当方向为 `对端网元` 时，查询路径必须经过对端 `ne` 后再连接 `alarm`，并排除起始网元自身。
- 当方向为 `业务路径` 时，查询路径必须经过 `businesspath` 和相关 `ne` 后再连接 `alarm`；`businesspath` 是对象类型，不能当作关系边。
- 业务路径设备名约束使用 `businesspath.aDeviceName = ${neName_service_path}` 或子图中确认的等价字段。
- 起点过滤使用该方向的起始网元名称：`ne.name = ${neName_<directionKey>}`。
- 告警过滤使用该方向的告警类型列表：`alarm.alarmName IN ${alarmNames_<directionKey>}`。
- 查询结果为空是有效结果，表示该方向未发现指定活动告警证据；不得自动放宽条件、换路径或重试。

### 返回要求和 message_type

网元字段必须保留：

```text
srcSpaceVid, name, className, domain, networkType
```

告警字段必须保留：

```text
node, ownerVid, severity, alarmName, identifier, firstOccurrence, lastOccurrence, clearTime
```

message_type：

| directionKey | message_type |
|---|---|
| `same_site` | `same_site_active_alarms` |
| `peer_ne` | `peer_ne_active_alarms` |
| `service_path` | `service_path_active_alarms` |

输出结构要求：只返回业务对象结构 `{objects, relationships}`，除非用户明确要求调试信息。

### Function 规则

默认不启用 Function。只有业务领域知识或用户问题明确要求 Function 补齐路径、参数或上下文，并且本体子图返回可信函数候选时，才在流程级定制中追加 S4/S5。

### 失败策略和禁止项

- 缺少方向时，填写 `缺少传播证据检查方向`。
- 缺少起始网元时，填写 `缺少起始网元名称`。
- 缺少告警列表时，填写 `缺少待验证告警类型列表`。
- 子图缺少必要对象、字段或关系时，保留缺失说明，不得自行补齐。
- 禁止自动补充用户未指定方向。
- 禁止查询 Port、Link 替代网元/告警证据查询。
- 禁止合并多个方向到一个查询任务。
- 禁止同一方向重复组织子图检索或数据查询。
- 禁止默认调用 Function。
- 禁止空结果后自动放宽条件、换路径或重试。

## 流程级定制

**默认填写：**

```text
使用默认流程 S1 -> S2 -> S3 -> S6；不执行 S4/S5 Function；每个方向独立处理；S3 空结果视为有效结果。
```

**可选覆盖：**

```text
如果业务领域知识明确要求 Function 补齐路径、参数或上下文，并且子图返回可信函数候选，使用流程 S1 -> S2 -> S4 -> S5 -> S3 -> S6。
```

**填写说明：**

- 只写相对默认流程的覆盖项。
- 传播证据验证默认不启用 Function。
- 多方向时保留“每个方向独立处理”。

## 步骤级定制

**默认填写：**

```text
S1：按用户指定方向检索起始网元、方向相关中间对象、相关网元和告警对象子图，关系名必须从子图 edges.properties.name 获取；S2：为每个方向独立生成查询任务，严格遵守同站点、对端网元、业务路径的查询约束；S3：按方向查询活动告警并返回 {objects, relationships}，使用该方向的网元变量、告警列表变量、返回字段和 message_type；S6：按方向汇总是否存在传播证据，空结果表示未发现该方向证据。
```

**填写说明：**

- 只写业务增量规则，不重复 Planning 默认步骤模板。
- 如果某一步无特殊业务规则，可写“使用默认步骤模板”。
- 必须保留“关系名动态获取”和“查询约束”中的强制规则。

**默认填写：**

```text
无
```

**填写规则：**

- 缺少起始网元时填写：`缺少起始网元名称`。
- 缺少检查方向时填写：`缺少传播证据检查方向`。
- 缺少告警列表时填写：`缺少待验证告警类型列表`。
