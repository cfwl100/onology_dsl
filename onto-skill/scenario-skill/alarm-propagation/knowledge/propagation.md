# 获取传播知识

## 目标
从知识本体 / KG 中获取本网元告警的传播关系、相邻告警分类、异常状态特征。

## 核心经验性知识

### 告警和异常事件不同
- **不要去查找 AbnormalStatus**（异常事件）
- 要查询活动告警

### 告警唯一标识符
- 告警的 `alarmName` 实际上是告警类型
- 告警的唯一标识符是 `identifier`
- 查询特定某条或某几条告警时，应该使用 `identifier` 字段

### 传播链理解

**PathNE（链型）传播规则**：
代表故障在拓扑链路上传播。根因判断方式：
- 先将拓扑上的网元编号：**无线端**为起点，从0开始顺序编号
- 多网元故障时：根因在**编号最大**和**次大**的故障网元中判定
- 业务路径上的根因判定规则：
  - 1）相邻网元均为网元离线或网元脱管故障，则上游故障影响下游故障；
  - 2）相邻网元上游为端口中断/链路中断故障、下游为网元离线或脱管故障，下游网元对应多个对端网元存在端口中断/链路中断或存在掉电告警或存在同机房/站点的动环告警，则根因网元为下游网元，其他情况单一上游网元端口中断/链路中断故障和下游网元离线或脱管且下游网元不包含硬件故障或电源/动环故障，根因为上游端口中断/链路中断。

**RingNE（环型）传播规则**：
代表故障在拓扑的环上传播：
- 先将环上网元编号：**核心侧**逆时针或顺时针从0开始顺序编号
- 多点开环时：根因在**编号最小**和**编号最大**的故障网元及其相邻网元中判定

**SingleNE（同网元）传播规则**：
- 代表故障在同一个网元中传播

**CrossNE（相邻网元）传播规则**：
- 代表故障在相邻网元中传播（相邻网元互相传播）

### Function 获取

通过 OAG 查询时，从 Alarm 对象的 `has_function` 边可获取该对象可调用的 Function 能力。
Function 不是对象类型，禁止对Function进行模型查询，对Function的操作请直接路由至函数执行。
 **Function查询只执行一次**：每个Function在整个执行阶段**只能调用一次**，禁止对同一个Function重复调用

## OAG 调用规则
- **Ontology ID**：调用 OAG 查询子图时，**必须**传入 `Ontology ID = network@1.0`
- **调用OAG语句强制要求**为：
`根据问题：网元和告警通过异常状态特征的传播链，从【告警（Alarm）】，查找到【异常状态特征】），先找相关子图，再按SOP规划任务`

## OAC 调用规则
- **schemaRef**：调用 OAC 执行实例查询时，如用户传入则必填（本体名字） `schemaRef = network@1.0`

## 执行建议

1. **首选**：通过 OAG 查询获取 Function（从 has_function 边），调用 Function 获取传播知识
2. **备选**：通过 OAG 查询 Alarm → AbnormalStatusPattern 关系，理解分类
3. **必须满足约束**：当调用Function获取到传播知识以后，无需再次进行OAC的备选方案的执行

**重要**：传入的传播知识子图/Function结果，不等于传播链已成立。必须经过实例验证才能确认。
