本文档用于业务定制开发人员维护“传播知识查询”场景的 Planning 输入内容。外层 `alarm-propagation/SKILL.md` 读取本文件时，应保留这里的传播 Know-how，并组装为 6 行输入后传递给 `Ontology-based-planning-skill`。

```text
network@1.0
```

固定填写公共本体 ID。

## 业务意图

```text
获取 ${target} 相关的告警传播知识，用于辅助传播分析。
```

`${target}` 是用户指定的告警、网元、网元类型、告警类型或传播分析目标。

## 业务领域知识

### 场景知识

传播知识查询用于从知识本体或知识图谱中获取本网元告警的传播关系、相邻告警分类、异常状态特征和传播分析知识。传播知识用于辅助分析，不等于实例层传播证据已经成立；是否成立仍需要由传播证据验证场景查询活动告警实例。

### 告警和异常事件边界

- 用户查询告警传播知识时，优先围绕告警和网元组织语义。
- 不要把告警查询误转成异常事件查询。
- 查询告警时关注 `alarm` 对象。
- `alarmName` 表示告警类型。
- `identifier` 表示告警唯一标识。

### 传播链类型知识

**PathNE（链型）传播规则：**

- 代表故障在拓扑链路上传播。
- 先将拓扑上的网元编号，无线端为起点，从 0 开始顺序编号。
- 多网元故障时，根因在编号最大和次大的故障网元中判定。
- 业务路径上，相邻网元均为网元离线或网元脱管故障时，上游故障影响下游故障。
- 相邻网元上游为端口中断或链路中断故障、下游为网元离线或脱管故障时，如果下游网元对应多个对端网元存在端口中断/链路中断，或存在掉电告警，或存在同机房/站点动环告警，则根因网元为下游网元。
- 其他情况下，如果单一上游网元端口中断/链路中断，且下游网元离线或脱管，并且下游网元不包含硬件故障、电源故障或动环故障，则根因为上游端口中断/链路中断。

**RingNE（环型）传播规则：**

- 代表故障在拓扑环上传播。
- 先将环上网元编号，核心侧逆时针或顺时针从 0 开始顺序编号。
- 多点开环时，根因在编号最小、编号最大及其相邻网元中判定。

**SingleNE（同网元）传播规则：**

- 代表故障在同一个网元中传播。

**CrossNE（相邻网元）传播规则：**

- 代表故障在相邻网元中传播，相邻网元可以互相传播。

### 子图检索规则

- 围绕 `${target}` 检索告警、网元、传播知识、异常状态特征、传播关系、相邻关系和函数能力候选。
- OAG 查询子图时使用 Ontology ID：`network@1.0`。
- OAG 子图问题围绕“网元和告警通过异常状态特征的传播链，从告警 Alarm 查找到异常状态特征，再找相关子图并按 SOP 规划任务”组织。
- 可以从 Alarm 对象的 `has_function` 边获取该对象可使用的函数能力。
- 函数能力不是对象类型，禁止把函数能力当作对象做模型查询。

### 任务规划规则

- 判断用户问题是查询传播关系、传播类型、相邻告警知识，还是为后续证据验证准备传播知识上下文。
- 如果子图返回可信函数能力，并且业务知识明确首选函数能力，则使用 S4/S5 分支。
- 未使用函数能力时，可通过告警、异常状态特征或传播知识结构返回知识结果。
- 每个函数能力在一次完整处理过程中只使用一次，禁止重复使用同一个函数能力。
- 当函数能力已经返回传播知识后，不再继续组织备选查询。

### 查询规则

- 查询实例或知识结构时，schemaRef 使用 `network@1.0`。
- 返回与 `${target}` 相关的传播知识结构，避免把知识定义误当成实例层活动告警结果。
- 如果要判断传播链是否成立，应转入传播证据验证场景，而不是直接用传播知识给出成立结论。

### 返回要求和失败策略

- 返回传播知识摘要、传播链类型、相关对象、相关函数能力和可用于后续证据验证的提示信息。
- 缺少 `${target}` 时，填写缺失信息，不得猜测补齐。
- 传播知识不等于传播证据成立，最终结论中必须保留该边界。
- 禁止把异常事件对象当作告警对象。
- 禁止把 `alarmName` 当作告警唯一标识。
- 禁止重复使用同一个函数能力。
- 禁止函数能力已返回传播知识后继续组织备选查询。

## 流程级定制

**默认填写：**

```text
使用默认流程 S1 -> S2 -> S3 -> S6。
```

**可选覆盖：**

```text
如需使用传播知识函数能力，且子图返回可信函数能力候选，使用流程 S1 -> S2 -> S4 -> S5 -> S6；函数能力已返回传播知识后，不再执行 S3 备选查询。
```

## 步骤级定制

**默认填写：**

```text
S1：围绕目标检索告警、网元、传播知识、异常状态特征、传播关系和函数能力候选子图；S2：判断查询传播关系、传播类型、相邻告警知识，还是为证据验证准备知识上下文，并决定是否使用函数能力；S3：在不使用函数能力时查询并返回传播知识结构；S4/S5：仅在子图返回可信函数能力候选且业务明确要求时使用，每个函数能力只使用一次；S6：汇总传播知识，并说明传播知识不等于实例层传播证据成立。
```
