# 查询传播关系

本文是 `alarm-propagation` 中“查询告警传播关系”意图的业务领域知识文件，采用当前六步格式组织。业务 Skill 读取本文后，将必要内容注入 Planning 顶层输入的 `业务领域知识`、`流程级定制`、`步骤级定制` 和 `缺失信息` 中。

## 0. 全局业务领域知识

目标：根据用户指定的告警类型、告警分类或传播主题，查询本体中定义的传播关系、影响关系或依赖关系，并返回可解释的关系结构。

核心知识：

- 传播关系查询关注的是本体层或关系知识层，不是实例层活动告警证据验证。
- 如果用户问“是否真的发生传播”，应转入 `propagation_evidence_check`。
- 如果用户只问“某类告警会影响哪些对象/告警/网元”，使用本文。
- 关系名称、方向和端点必须来自 OAG 子图，不得凭经验硬编码。
- 输出应保留对象、关系、方向、端点、规则来源和缺失项。

## 1. 流程级定制

默认流程：

```text
S1 -> S2 -> S3 -> S6
```

默认不使用 Function。只有业务领域知识明确要求用函数补齐传播规则或外部规则库结果时，才追加 S4/S5。

## 2. S1 子图检索

输入模板：

```text
检索本体子图
本体ID：<本体ID>
业务意图：查询指定告警或告警分类的传播关系
业务领域知识：传播关系、影响关系、依赖关系、端点对象和返回要求
步骤级定制：传播关系子图检索规则
检索目标：查找告警、网元、业务对象、传播关系、影响关系和依赖关系相关的对象、字段和关系
返回结构要求：保留 nodes、edges、关系名称、关系方向、端点对象类型、规则来源和缺失项
```

输出模板：

```text
subgraphOutput：
- rawSubgraph：OAG 返回的原始图结构
- objectCandidates：告警、网元、业务对象或传播规则对象
- relationCandidates：传播/影响/依赖关系候选
- propertyCandidates：关系和对象的属性归属
- missingItems：缺失对象、关系、方向或字段
```

执行规则：

- 只依据 OAG 返回的关系事实规划后续查询。
- 如果没有传播关系候选，进入 S6 输出“未发现传播关系定义”。

## 3. S2 基于本体子图的任务规划

输入模板：

```text
基于本体子图规划执行任务
本体ID：<本体ID>
业务意图：查询指定告警或告警分类的传播关系
本体子图：<S1.subgraphOutput.rawSubgraph>
业务领域知识：传播关系查询范围、方向、端点、返回字段和失败策略
步骤级定制：传播关系任务规划规则
规划目标：从起点告警或对象出发，规划关系查询或关联查询任务
```

规划规则：

- 根据 S1 子图确定起点对象、终点对象和关系方向。
- 如果用户指定告警类型，使用告警类型字段作为过滤条件。
- 如果用户指定告警标识，优先使用唯一标识字段。
- 如果用户只指定传播主题，返回关系结构，不强行查询实例告警。

输出模板：

```text
plannedTasks：
- taskType：RELATION_QUERY 或 ASSOCIATION_QUERY
- operationType：QUERY 或 ASSOCIATION_QUERY
- objectPlan：起点对象、终点对象
- relationPathPlan：传播关系路径、方向、端点
- filterPlan：用户指定告警类型、对象类型或规则名称
- returnPlan：关系名称、方向、端点对象、规则摘要
- failurePolicy：无关系候选时进入 S6 汇总
```

## 4. S3 OAC 查询

输入模板：

```text
查数据
本体ID：<本体ID>
操作类型：来自 S2.plannedTasks
查询对象：来自 S2.plannedTasks.objectPlan
关系路径：来自 S2.plannedTasks.relationPathPlan
过滤条件：来自 S2.plannedTasks.filterPlan
返回要求：返回传播关系、端点对象、方向、规则摘要和缺失项
期望输出：只返回对象结构 {objects, relationships}
```

输出模板：

```json
{
  "objects": [],
  "relationships": []
}
```

失败策略：

- 空结果表示未发现匹配传播关系定义。
- 不自动改写成实例告警查询。
- 不自动转入传播证据验证，除非用户明确要求。

## 5. S4/S5 Function 发现与执行

默认不使用 Function。

如果业务领域知识明确要求从外部规则库或算法服务补齐传播关系，并且 S1 返回可信函数候选，则允许使用 S4/S5。

函数输出必须映射到 S6 可解释的关系结构，不得替代 OAG 已返回的本体事实。

## 6. S6 汇总

输入模板：

```text
汇总传播关系查询结果
业务意图：<业务意图>
业务领域知识：传播关系解释、空结果解释、展示要求
上游结果：S1 子图摘要、S2 规划摘要、S3 OAC 对象结构、可选 S5 函数结果
```

输出模板：

```text
finalAnswer：
- relationStatus：FOUND | NOT_FOUND | MISSING_INFO | FAILED
- relationSummary：传播关系摘要
- sourceObjects：起点对象
- targetObjects：终点对象
- relationships：关系名称、方向、端点
- missingItems：缺失项
- nextAction：是否需要转入传播证据验证
```

汇总规则：

- 非空关系结构表示发现传播关系定义。
- 空结果表示未发现匹配关系定义。
- 必须区分“传播关系定义存在”和“实例层传播证据存在”。
- 不重新执行上游步骤。

## 7. 禁止项

- 禁止把传播关系查询自动改写为活动告警查询。
- 禁止把关系定义结果当成实例层传播证据。
- 禁止凭经验硬编码关系名、方向和端点对象。
- 禁止编造 OAG/OAC 未返回的关系或对象。
