# Ontology-based-planning-skill 对外输入接口

本文档定义业务定制 Skill 传给 `Ontology-based-planning-skill` 的对外输入协议。该协议面向业务开发人员和 Agent 运行时，目标是减少重复解析、降低上下文开销，并保证业务知识能够稳定传递到规划层。

## 1. 适用范围

适用于 `onto-skill/scenario-skill` 下的所有业务定制 Skill。

业务定制 Skill 的职责是：识别业务意图、读取业务知识、抽取变量、组装 6 行输入，并把结果传给 `Ontology-based-planning-skill`。

业务定制 Skill 不负责执行 OAG、OAC、Function，不生成 OQL，不调用真实后端。

## 2. 顶层输入格式

业务定制 Skill 只输出以下 6 行。字段名、顺序和中文冒号建议保持一致。

```text
本体ID：<公共本体ID>
业务意图：<详细自然语言问题>
业务领域知识：<本次执行需要的场景知识、业务规则、子图检索规则、任务规划规则、查询规则、Function 规则、返回要求和失败策略；没有则写无>
流程级定制：<只填写相对默认流程的覆盖项；无覆盖写“使用默认流程”>
步骤级定制：<只填写相对默认步骤模板的业务增量规则；无增量写“使用默认步骤模板”>
缺失信息：<没有则写无>
```

## 3. 字段说明

| 字段 | 填写要求 | 说明 |
|---|---|---|
| 本体ID | 填写一个公共本体ID | 作为 OAG 检索范围和 OAC `schemaRef` 来源 |
| 业务意图 | 填写完整业务问题 | 由业务 Skill 根据用户问题和业务语义改写，不写平台执行细节 |
| 业务领域知识 | 填写本次任务所需全部业务上下文 | 包含场景知识、对象/字段/关系约束、查询规则、返回要求、失败策略 |
| 流程级定制 | 只写默认流程差异 | 无差异写“使用默认流程” |
| 步骤级定制 | 只写步骤级业务增量 | 无增量写“使用默认步骤模板” |
| 缺失信息 | 写缺失变量或规则 | 无缺失写“无” |

## 4. 业务领域知识填写建议

`业务领域知识` 是承载业务 Know-how 的主字段。业务 Skill 组装时应尽量保留原始业务规则，不要只写摘要。

建议包含以下内容：

- 场景知识：业务场景、术语解释、对象边界。
- 业务规则：方向规则、判断规则、优先级、禁止项。
- 子图检索规则：需要检索的对象、字段、关系、函数候选。
- 任务规划规则：路径选择、对象选择、关系动态获取、任务拆分。
- 查询规则：过滤条件、返回字段、空结果策略、最大条数。
- Function 规则：是否启用、候选来源、参数来源、失败处理。
- 返回要求和失败策略：最终结果形态、缺失信息、冲突信息、失败解释。

## 5. 流程级定制

默认流程为：

```text
S1 -> S2 -> S3 -> S6
```

含义：先检索子图，再基于子图规划任务，再执行 OAC 数据访问，最后汇总。

如需 Function 能力，可在流程级定制中明确，例如：

```text
S1 -> S2 -> S4 -> S5 -> S3 -> S6
```

如果业务要求多方向、多对象或多路径独立执行，应在该字段说明。例如：

```text
同站点、对端网元、业务路径三个方向分别独立执行默认流程，最后统一汇总。
```

## 6. 步骤级定制

步骤级定制只写相对默认步骤模板的业务增量，不重复写通用输入输出模板。

示例：

```text
S1 使用同站点子图检索规则；S2 关系名必须从子图 edges.properties.name 动态获取；S3 空结果视为有效结果；S6 按方向输出证据摘要。
```

## 7. 标准步骤

| 步骤 | 名称 | 默认职责 |
|---|---|---|
| S1 | 子图检索 | 根据本体ID、业务意图和业务领域知识获取本体子图 |
| S2 | 基于本体子图的任务规划 | 基于子图事实生成 OAC / Function / 汇总任务计划 |
| S3 | OAC 数据访问 | 生成、校验并按需执行 OQL，输出对象结构 |
| S4 | Function 发现 | 从子图或业务规则中选择函数候选 |
| S5 | Function 执行 | 获取参数规格并按规则调用函数能力 |
| S6 | 汇总 | 汇总对象结构、函数结果、缺失项和失败原因 |

## 8. Planning 运行时约束

`Ontology-based-planning-skill` 运行时直接读取 6 行原文，不再把 6 行内容重复映射为新的字段对象，也不再构造 `planningContext`、`inputGate` 或 `stepRuleMap`。

Planning 层只保留必要的执行链判断：根据“流程级定制”生成 `executionPlan`，再按执行计划逐步消费 6 行原文、步骤级业务增量和上游步骤输出。

## 9. 业务 Skill 组装约束

业务 Skill 可以读取一个或多个 Markdown 知识文件，但最终只能向 Planning 输出一个 6 行输入块。

如果 knowledge 文件中存在“可注入 6 行片段”，该片段只能作为骨架。业务 Skill 必须把相关细粒度业务规则合并到 `业务领域知识` 行中，不能因为使用片段而丢失原始 Know-how。

## 10. 输出约束

业务 Skill 输出给 Planning 时，不追加 JSON、YAML、`stepContracts`、`planningDelegationPackage`、字段映射表或调试结构。

最终对 Planning 的唯一输入就是 6 行文本。
