# OAC 自然语言模板格式校验

本文件定义 `oac-natural-language-template.md` 的通用软校验规则。软校验只判断模板字段是否足够生成 OQL，不判断具体业务语义是否正确。

## 是否有必要

有必要。原因如下：

1. 前端可以在提交给 OAC 前发现缺失字段。
2. Agent 可以根据错误提示提前补齐信息，减少生成无效 OQL。
3. 校验规则只覆盖平台通用字段，不包含 SEC、告警、港口等业务规则，不破坏平台稳态。

## 校验范围

校验以下通用字段：

- schemaRef
- 操作类型
- 查询对象
- 关系路径
- 过滤条件
- 返回字段
- 聚合要求
- 排序/限制
- 时间要求
- 扩展说明
- 结果处理

## 必填规则

1. `操作类型` 必填，可以使用中文自然语言，例如“查询明细”“按关系路径查询”“统计数量”。
2. `查询对象` 必填，需要说明对象类型、对象别名或业务对象范围。
3. `返回字段` 必填，需要说明返回哪个对象或关系的哪些字段。
4. 当操作类型表达关系、路径、遍历、归属、一跳、多跳等含义时，`关系路径` 必填。
5. 当操作类型表达统计、聚合、分组、计数、求和、平均、最大、最小等含义时，`聚合要求` 必填。
6. `schemaRef` 可选；如果未填写，则执行环境必须提供 `ONTOLOGY_SCHEMA_REF`。

## 纠正规则

1. 操作类型过于模糊时，提示补充操作选择依据。
2. 只说明本地时间或 UTC 时间但没有时间范围时，提示补充过滤条件。
3. 扩展说明包含 `localtime` 时，值只能是 `true` 或 `false`。
4. 用户明确指定返回字段时，不应生成 `*`。

## 校验脚本

脚本位置：

`../scripts/validate_oac_nl_template.py`

输入是模板字段 JSON。字段名可以使用英文名，也可以使用中文模板字段名。

示例：

```bash
python scripts/validate_oac_nl_template.py --template-json '{"操作类型":"查询明细","查询对象":"cell 别名 c","返回字段":"c.C_RSRP"}'
```

输出包含：

- `valid`：是否通过必填校验
- `errors`：必须修正的问题
- `warnings`：建议补充的问题
- `normalized`：归一化后的字段

当 `valid=false` 时，应先根据 `errors` 补齐模板字段，再进入 OQL 生成。
