# 本体数据访问（OAC）

## 本层职责
OAC 是本体平台的数据访问层，面向本体对象提供查询、聚合、路径遍历、创建、更新、删除等数据访问能力。

## 操作类型
OAC 支持三种操作类型：

| 操作类型 | 说明 | 适用场景 |
|---------|------|---------|
| **QUERY** | 无关联的对象查询 | 单对象查询、不涉及对象间关系遍历 |
| **ASSOCIATION_QUERY** | 关联查询 | 多跳关系遍历、路径查询、起点终点与中间节点联合约束 |
| **AGGREGATE** | 聚合查询 | 分组统计、指标计算、聚合后过滤 |

## 路由判断
判断使用哪种操作：
- 用户只说"查XX的哪些属性"、查xx和xx的哪些属性、"没有提到对象间关系" → **QUERY**
- 用户明确提到"关系"、"路径"、"遍历"、"连接"、"经过" → **ASSOCIATION_QUERY**
- 用户明确提到"统计"、"聚合" → **AGGREGATE**

## OAC 自然语言委托模板

上层业务 Skill 可以使用自然语言委托本体平台的数据访问能力。委托内容应尽量完整、明确，便于本层根据本体对象、关系、条件和返回要求生成 OQL。

推荐模板如下：

```text
请调用本体平台的数据访问能力，按如下要求生成并执行 OQL：

1. schemaRef：<本体 schema 标识，例如 network@1.0 或 ams_topology@1.0>
2. 操作类型：<QUERY / ASSOCIATION_QUERY / AGGREGATE>
3. 操作选择依据：<为什么选择该操作；例如不涉及关系遍历、需要沿关系路径查询、需要分组统计>
4. 查询对象：<对象类型、别名、对象职责；例如 grid 别名 g，cell 别名 c>
5. 关系路径：<仅 ASSOCIATION_QUERY 必填；写明起点对象、终点对象、关系方向、关系名来源；QUERY/AGGREGATE 无关系路径时写“无”>
6. 过滤条件：<字段归属对象、字段名、操作符、取值；时间范围也必须写在过滤条件中>
7. 返回字段：<返回哪个对象或关系的哪些字段；用户指定字段时不要使用 *>
8. 聚合要求：<仅 AGGREGATE 填写；包括分组字段、指标函数、指标别名、聚合后过滤条件；非聚合写“无”>
9. 排序/限制：<排序字段、升降序、最大返回条数；无要求写“无”>
10. 时间要求：<时间字段、时间范围、时间口径；本地时间/UTC 时间只表示时间口径，不能替代过滤条件>
11. 扩展说明：<只填写已约定扩展参数；无明确约定时写“无”。例如时间属性描述为本地时间时，要求 extensions.localtime="true"；描述为 UTC 时间时，要求 extensions.localtime="false">
12. 结果处理：<结果为空是否结束、是否需要保留原始字段、是否需要给出摘要说明>
```

填写要求：

1. `操作类型` 必须从 OAC 已支持的操作类型中选择。
2. `查询对象` 中的别名必须和过滤条件、返回字段中的引用保持一致。
3. `关系路径` 只在关联查询中填写；无关系路径时不要为了补全模板而臆造关系。
4. `过滤条件` 必须写清字段归属对象，避免把 A 对象字段写到 B 对象上。
5. `聚合要求` 只在聚合查询中填写；不要把聚合后过滤写成普通过滤条件。
6. `扩展说明` 只用于补充 OQL 的 `extensions` 字段，不得替代标准对象、关系、条件、返回字段。
7. 时间范围必须进入标准过滤条件；`extensions.localtime` 只表达时间口径。

### 模板示例：带 localtime 扩展

```text
请调用本体平台的数据访问能力，按如下要求生成并执行 OQL：

1. schemaRef：ams_topology@1.0
2. 操作类型：QUERY
3. 操作选择依据：查询单对象指标明细，不需要沿对象关系遍历。
4. 查询对象：cell，别名 c。
5. 关系路径：无。
6. 过滤条件：c.CELL_ID 等于 B；c.property1 大于等于开始时间；c.property1 小于结束时间。
7. 返回字段：c.CELL_ID、c.C_PRB。
8. 聚合要求：无。
9. 排序/限制：最多返回 100 条。
10. 时间要求：property1 是时间类型属性；根据属性描述识别为本地时间；时间范围必须写入过滤条件。
11. 扩展说明：如果生成 OQL 支持 extensions，请添加 extensions.localtime="true"。
12. 结果处理：结果为空即返回空，不要改写条件重试。
```

对应 OQL 扩展片段示例：

```json
"extensions": {
  "localtime": "true"
}
```

## OQL 扩展字段 extensions

OQL 可选支持 `extensions` 字段。该字段用于承载业务侧与 OAC 已经约定的扩展参数；无明确约定时应省略。

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---:|---|
| `extensions` | object | 否 | 扩展字段；无明确约定时应省略。 |

使用规则：

1. `extensions` 只能填写已约定的扩展参数。
2. 无明确扩展含义时不生成该字段。
3. `extensions` 不能替代 `conditions`；时间范围、对象过滤、指标过滤仍应写入标准条件。
4. 如果业务 Skill 根据对象时间属性描述识别出时间口径，可以表达 `localtime` 扩展：描述为本地时间时填写 `localtime` 为 `"true"`；描述为 UTC 时间时填写 `localtime` 为 `"false"`。
5. `localtime` 只表示时间口径，不表示时间范围。
