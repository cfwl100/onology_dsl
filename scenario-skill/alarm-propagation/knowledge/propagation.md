# 获取传播知识

## 目标

从知识本体 / KG 中获取本网元告警的传播关系、相邻告警分类、异常状态特征。

## 核心概念

### 告警与异常事件的区别

- **告警**和**异常事件**不同
- **不要**去查找 `AbnormalStatus`（异常事件）
- 要查询**活动告警**

### 告警唯一标识符

- 告警的 `alarmName` 实际上是**告警类型**
- 告警的**唯一标识符**是 `identifier`
- 查询特定某条或某几条告警时，应该使用 `identifier` 字段

## 传播链类型

### PathNE（链型）传播规则

代表故障在拓扑链路上传播。根因判断方式：

1. **编号规则**：先将拓扑上的网元编号，**无线端**为起点，从0开始顺序编号
2. **多网元故障**：根因在**编号最大**和**次大**的故障网元中判定
3. **根因判定规则**：
   - 相邻网元均为网元离线或网元脱管故障 → 上游故障影响下游故障
   - 相邻网元上游为端口中断/链路中断故障、下游为网元离线或脱管故障：
     - 下游网元对应多个对端网元存在端口中断/链路中断或存在掉电告警或存在同机房/站点的动环告警 → 根因网元为下游网元
     - 其他情况 → 根因为上游端口中断/链路中断故障

### RingNE（环型）传播规则

代表故障在拓扑的环上传播：

1. **编号规则**：先将环上网元编号，**核心侧**逆时针或顺时针从0开始顺序编号
2. **多点开环**：根因在**编号最小**和**编号最大**的故障网元及其相邻网元中判定

### SingleNE（同网元）传播规则

代表故障在**同一个网元**中传播。

### CrossNE（相邻网元）传播规则

代表故障在**相邻网元**中传播（相邻网元互相传播）。

## Function 获取

通过 OAG 查询时，从 Alarm 对象的 `has_function` 边可获取该对象可调用的 Function 能力。

**约束**：
- Function 不是对象类型，**禁止**对 Function 进行模型查询
- 对 Function 的操作请直接路由至函数执行
- **Function 查询只执行一次**：每个 Function 在整个执行阶段**只能调用一次**，禁止对同一个 Function 重复调用

## 重要说明

传入的传播知识子图 / Function 结果，**不等于传播链已成立**。必须经过实例验证才能确认。
