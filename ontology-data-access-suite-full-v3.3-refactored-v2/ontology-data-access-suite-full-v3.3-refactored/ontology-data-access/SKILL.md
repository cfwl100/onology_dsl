# 本体对象数据访问

本层是稳定入口，只负责识别用户想做什么、还缺什么、应该交给哪一类下层实现。

## 职责
1. 识别普通读取、统计聚合、路径读取、关联导航、创建、更新、删除、存在则更新、批量写入等意图。
2. 判断请求是否缺少对象范围、关系类型、筛选条件、返回内容、匹配键、写入内容或执行范围。
3. 仅在意图已经稳定时，选择一个最合适的下层实现。
4. 当用户已经给出完整结构化请求时，直接交给执行层，不在本层补写、改写或解释。

## 路由线索
- 读取单类对象，且不需要显式关系路径 → 选择普通对象读取实现
- 统计、分组、计数、求和、平均值、最值、排行 → 选择聚合读取实现
- 明确给出多跳路径、路径起点终点或中间节点约束 → 选择路径读取实现
- 明确是一跳关系导航，从源对象取关联对象 → 选择一跳关联实现
- 新增一个对象 → 选择创建实现
- 按条件修改已有对象 → 选择更新实现
- 按条件删除已有对象 → 选择删除实现
- 存在则更新，否则创建；或多个写步骤要一起提交 → 选择对应的写入实现
- 已经给出完整结构化请求，只差执行 → 直接交给执行层

## 本层边界
- 不在本层讲解内部字段名、结构细节或转换步骤。
- 不在本层猜测对象、关系、字段、匹配键、关系方向或删除范围。
- 不在本层把一个复杂需求默认拆成多个写请求，除非用户明确要求。
- 不在本层替下层做约束校验细节说明。

## 输出原则
- 如果意图明确且信息完整，交给唯一最合适的下层实现。
- 如果信息不足，明确指出缺少的关键信息。
- 如果用户已经提供完整结构化请求，不再要求重复描述自然语言意图。
